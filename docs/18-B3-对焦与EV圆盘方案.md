## 一、SDK 硬事实（Mac 侧读 iOS 26 SDK `AVCaptureDevice.h`，2026-09-19）

| 行号 | SDK 明文 | 后果 |
|---|---|---|
| **538-541** | 虚拟设备（builtInTripleCamera / DualCamera 等）只允许锁 **Current**：`.custom` 曝光、自定义 lensPosition 的焦点锁定、非 Current 的白平衡增益锁定**全部不支持** | B2/B3 的手动参数在虚拟会话下**全都做不了**；传计算值即抛 ObjC 异常 |
| **1601** | `isLockingWhiteBalanceWithCustomDeviceGainsSupported` —— 白平衡"锁自定义增益"的**正确**探测 | 虚拟设备上 false。旧守卫 `isWhiteBalanceModeSupported(.locked)` 误报 true → 7 连崩（已修，`check_swift.js` 第 12 组⑯守着） |
| **1110** | `isLockingFocusWithCustomLensPositionSupported` —— 对焦"锁自定义镜头位置"的**正确**探测 | 虚拟设备上 false。`setManualFocus` 的守卫已同步换掉（同类预警全仓唯一一处已处理） |

> 全仓排查结论：`setWhiteBalanceModeLocked` 与 `setFocusModeLocked(lensPosition:)` 的全部调用点
> 都在 `CaptureDeviceConfigurator`（铁律 2），三处守卫本轮已全部换成正确探测 API。

## 二、架构改造：按焦段挂载物理设备（第二步施工图）

### 2.1 为什么必须换

虚拟多摄的三条手动能力全被 SDK 关死（上表）。选 **方案 A（物理设备）**：拍手动参数时，
会话挂载的是**物理单摄**，能力探测全为 true，手动档全部可用。

### 2.2 焦段 → 物理设备映射

| 焦段档 | 挂载设备 | 说明 |
|---|---|---|
| 13mm | `builtInUltraWideCamera` | 原生视场 |
| 24mm / 35mm / 48mm | `builtInWideAngleCamera` | 35/48 = 主摄数码裁切（沿用 `FocalPreset.mainCropFactor`） |
| 120mm | `builtInTelephotoCamera` | 原生视场 |

- 回退规则沿用 B1 的镜头探测（`CaptureCapabilities.hasUltraWideLens / hasTelephotoLens`）：
  没有那颗镜头的机型，对应档位照旧置灰（灰但仍可点，点了给原因）。
- **自动档模式不强制切物理设备**：纯取景 / 自动曝光 / 自动白平衡下，虚拟多摄的平滑变焦体验更好。
  **何时切物理**：① 用户进入任一手动档（ISO/快门、白平衡、手动对焦）；② 或统一策略
  "物理设备会话常驻"（见 2.6 拍板点 ①）。

### 2.3 跨切换点换设备流程（如 24mm → 120mm）

```
sessionQueue 上串行执行：
1. beginConfiguration
2. removeInput(旧物理 input)
3. addInput(新物理 AVCaptureDeviceInput)
4. 把用户已设的手动参数重新应用到新设备（见 2.4 参数搬运）
5. commitConfiguration
6. 之后才能写 activeFormat / 帧率（铁律 1 的顺序不变）
```

与 `buildSession()` 同款幂等与顺序纪律；`.inputPriority` preset 不变。

### 2.4 参数搬运边界（Mac 报告结论，逐条接住）

| 参数 | 能否搬 | 做法 |
|---|---|---|
| ISO / 快门 | ✅ | 两颗设备都支持 `.custom`；先 clamp 到**新设备 activeFormat** 的范围再 `setExposureModeCustom`（越界抛异常，铁律 2） |
| 白平衡 | ✅ | 物理设备支持锁定增益；初值取**旧设备当前色温**（`currentTemperature(of:)`，冷启动兜底 5600K 那套已就位），色调跟随新设备当前值 |
| 对焦 | ⚠️ 部分 | 每颗镜头 `lensPosition` 物理量程不同，旧值搬过去**可能对不上焦** → 搬运后二选一：a) 重跑一次自动对焦再回锁；b) 直接落回连续自动对焦兜底（留痕 + toast）。默认 b（简单可靠），a 作为增强项 |

### 2.5 变焦重做（B1 语义变化）

- 物理设备没有 ramp 跨镜头：**同镜头内**仍可 `videoZoomFactor` 平滑（数码），**跨切换点 = 换设备**，
  `videoZoomFactor` 直接赋值 → 画面**会跳一下**（系统级行为，掩盖手段见第三章转场）。
- `applyZoomRamp`（B1 那套）保留给虚拟设备会话；物理会话下焦段条点击走"换设备 + 模糊转场"，
  条内拖动（若有）走数码 zoom。两条路径由**当前会话挂的是虚拟还是物理**分派，收敛在
  `CaptureSessionController` 一个入口，不散在 UI。
- 自检第 11 组"切镜头路径只做 lock→ramp→unlock（无 beginConfiguration / input 增删）"这条守卫
  **要改**：物理路径恰恰要 begin/commit + input 增删 —— 改成"虚拟路径不得增删 input；
  物理路径的增删只能在 `CaptureSessionController` 的换设备方法里"。

### 2.6 拍板点

1. **物理设备会话是"常驻"还是"按需"？** 常驻 = 进 App 就挂物理设备（实现简单、变焦全靠跳+转场）；
   按需 = 自动态用虚拟、进手动档才切物理（体验最优但要管理两种会话形态）。**建议：按需**。
2. **"手动模式下不锁焦段"的执行口径**：我按"手动档不解锁焦段条 —— 仍可切换，跨切换点走参数搬运"
   理解并实现（这正是参数搬运的主场景）。若本意是"手动档下禁切焦段"，此处改为置灰，工程量更小。
3. 录制中（视频 / Live）**禁止换设备**（与"录制中禁止切模式"同款守卫），切焦段入口给 toast。

## 三、模糊转场（补充需求 · 方案 B · 已拍板推荐）

**目的**：掩盖物理设备切换瞬间的预览黑屏、参数跳变、对焦偏移 —— 飓风相机同款"模糊→清晰"。

### 3.1 实现

- **挂载点**：`PreviewView`（已是 `UIViewRepresentable` 包 `AVCaptureVideoPreviewLayer`）
  内部叠一个 `UIVisualEffectView(effect: UIBlurEffect(style: .regular))`，盖满预览层。
  **不参与任何相机逻辑**，纯视觉浮层。
- **驱动**：分层纪律 —— 会话层不碰 UI。`CaptureSessionController` 发布
  `@Published private(set) var isLensSwitching = false`（换设备方法入口置 true、commit + 参数搬运
  完成置 false）；`CameraView` 观察它驱动模糊浮层的进出场。
- **时序**（时长做成 `Theme` 令牌 + 量级守卫）：
  1. 点焦段（物理会话 / 跨切换点）→ `isLensSwitching = true` → 模糊透明度 **0 → 1，0.15s**；
  2. `beginConfiguration → 换 input → 搬参数 → commitConfiguration`；
  3. 完成 → `isLensSwitching = false` → 模糊 **1 → 0，0.25s**。
- **关键点**（用户原话接住）：动画时长与切换耗时**同源调参**——切换实测快（~100ms）模糊就短、
  慢（~300ms）就长；黑屏发生在 commit 前后，模糊峰值盖住它。

### 3.2 约束

- 转场期间**禁点**焦段条（防连点叠两个换设备流程）；录制中本来就不给切。
- 转场是**纯 UI**：不加进 `collapseOverlays()`（它不是"扩展浮层"，没有互斥语义）。

## 四、B3 本体：对焦与 EV 圆盘（#8）

### 4.1 EV 圆盘（先行，虚拟设备可用）

- EV 补偿走 `setExposureTargetBias`，只在**自动曝光档**共存时有效（`docs/16` 第五节、`docs/01`）。
- **编辑态闸门接 `docs/14` 同款**（已实测踩过的回写环）：
  拖动期 `isEditing` 闸门不回写 + 只接受与最后推送值一致的回写；`CameraViewModel` 已有
  `lastPushedExposureBias` 那套，圆盘复用同一状态，不另起炉灶。
- **EV 圆盘加进 `collapseOverlays()`（第 4 样）**：`collapseOverlays()` 现收 3 样（参数排 / 滤镜条 /
  场景·风格）+ 刻度条经 `dismissParamStripIfNeeded`；圆盘是**新浮层**，必须同时进
  `collapseOverlays()` 与 `dismissTransientPopovers()`，且**展开者自己不能调后者**
  （会收掉刚展开的自己 —— 2026-09-18 踩过的坑）。同时它与刻度条/参数排**同槽互斥**
  （同占图标行下那一行，净可见账不变）。
- 参数范围：沿用 `Float.evUIRange = ±2 ∩ 设备范围`（13 档 / 每档 ~28pt）。

### 4.2 对焦圆盘（UI 随 B3，硬件生效等架构）

- UI 与接线随 B3 落地：圆盘 0~1 → `setManualFocus(lensPosition:)`；能力探测
  `isLockingFocusWithCustomLensPositionSupported`（本轮已换）为 false 时**置灰 + toast 说明**
  （灰但仍可点）—— 虚拟多摄上就是置灰态，架构落地后自动点亮。
- 点按对焦（取景器点按）与手动对焦的关系：点按会走 `setFocusAndExposurePoint`（自动档），
  手动锁定后点按是否解锁 → **拍板点**：建议手动锁定期间点按对焦只做测光、不动焦
  （与系统相机一致），圆盘上给"回到自动"按钮。

### 4.3 自检计划（新增守卫，全部要做变异测试）

| # | 守卫 | 放哪 |
|---|---|---|
| 1 | EV 圆盘在 `collapseOverlays()` + `dismissTransientPopovers()` 两处都有；展开者不调后者 | check_swift 第 8 组同款 |
| 2 | EV 圆盘编辑态闸门：拖动期不回写 + 只接受最后推送值（`methodBodyOf` 切方法体） | 新增或第 8 组 |
| 3 | 圆盘与刻度条/参数排同槽互斥（`if … else if …` 收口） | 第 12 组⑨ 同款 |
| 4 | 对焦写入只在 `CaptureDeviceConfigurator`（`setFocusModeLocked` 唯一入口） | 第 12 组⑤ 同款 |
| 5 | 物理换设备路径：input 增删只在 `CaptureSessionController` 换设备方法；录制中禁止换设备 | 第 11 组改造 |
| 6 | 转场时长令牌量级（0.1~0.4s）与 `isLensSwitching` 发布位存在 | 新增 |
| 7 | 净可见账：圆盘行高入表，逐机型复算 ≥ 50% | 第 12 组⑩ |

## 六、代价与风险（用户拍板用）

| 项 | 内容 |
|---|---|
| 改动大 | `CaptureSessionController` 的 input 管理重写（换设备 + 参数搬运 + 幂等），B1 的 ramp 路径要按会话形态分派 |

| 不做会怎样 | B2/B3 手动档永远置灰 —— 手动参数这条产品线整体不可用 |
