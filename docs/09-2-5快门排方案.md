## 三、放大态规格（2-5b）

原型把放大态做成"**取景器卡片化 + 底栈让位**"，四件事同时发生：

| # | 变化 | 原型值 |
|---|---|---|
| 1 | **取景器卡片化** | `top: 86px`（= 状态栏 30 + 顶栏 56）、`bottom: 124px`（= 快门排 106 + 安全区 18）、`border-radius: 18px`、**左右不内缩**（用户反馈过"卡片比常态窄"，所以只收上下沿 + 圆角） |
| 2 | **焦段条浮进卡片内底边** | 脱离底栈文档流：`position:absolute; left:0; right:0; bottom:136px; height:44px; z-index:6`（136 = 卡底偏移 124 + 12 间隙） |
| 3 | **三条浮层整行归零** | 参数排 / 场景风格条 / 滤镜条：`height:0 + opacity:0 + pointer-events:none`（滤镜条不拦住的话，上划会在放大态叠出鬼影） |
| 4 | **快门排放大** | 行高 80 → **106**；`--shutter-scale: 1 → 1.3`；左右组转 **column**（`justify-content:space-between; padding:3px 0`）：镜像按钮在上、缩略图/风格方块在下 |

**镜像按钮**（放大态的「前置」「设置」）：
- `50×44`，图标 **19px** —— 比 7 图标行的 17px **大一档，这就是"放大"**
- 图标 + 文字竖排叠在缩略图 / 风格方块**正上方**
- 淡入动画 `mirrorIn .25s`（`opacity 0→1` + `scale .86→1`）
- 它们的作用：图标行整行收起后，前置与设置**仍有入口**

**净可见预算**（原型 826px 基准）：`826 − 86 − 124 = 616px · 74.6%`；焦段条 44px 浮层保守计入 → **69.2%**，仍 ≥ 50% ✓。
（Swift 侧屏高不同，验的是**同一条不变量**：放大态下取景器净可见 ≥ 50%）

**Swift 侧要特别小心的一点**：取景器卡片化改的是**预览容器的 inset**，
而 `FocusIndicatorView`（对焦框）与 `GridOverlayView`（三分线）**与预览同容器**
→ 坐标系天然跟随，**千万不要单独给它们加 inset**，否则对焦框会整体偏。

## 四、原型踩过的两个坑（照抄，别再踩）

### 坑 1 · ⤢ 的按压态不能整体替换 transform

原型注释（第 644–646 行）写得很直接：`:active` 若写成 `transform: scale(.95)`，
会把居中的 `translateY(-50%)` **整个换掉** → 按钮按下瞬间下跳 22px、指针悬空、
click 落到父级 `.shutter-row` —— 结果 **⤢ 永远点不着**（他们用 Playwright 实测出来的）。

**Swift 侧同理**：按压反馈别用会整体替换 transform 的写法（`scaleEffect` 叠在已有的
`offset` 上才安全），否则命中区会跟着一起偏。

### 坑 2 · 放大态的镜像按钮必须"不占位"

原型用 `display: none` 而不是 `visibility: hidden`。**后者会占位** ——
把 ⤢ 顶进快门的命中区（实测踩过）。

Swift 侧对应：隐藏用**条件插入**（`if isZoomOn { ... }`）而不是 `opacity(0)` / `hidden()`
之类仍参与布局的写法。

## 五、决策 #2 · 视频入库后左下角缩略图不更新（放进 2-5a）

**现象**：录完视频入库，左下角缩略图不变。日志里是 `缩略图生成失败（非图片文件），跳过`。

**根因**：`ThumbnailCache.rememberCapturedFile(at:)` 用 `CGImageSource` 去读 MOV
—— 它只认静态图，视频必然返回 nil。

**修法**（`Core/ImagePipeline/ThumbnailCache.swift`）：静态图那条路保留，
拿不到就用 `AVAssetImageGenerator` 抽首帧：

```swift
// 伪代码，实现时补齐错误处理与日志
let asset = AVURLAsset(url: url)
let generator = AVAssetImageGenerator(asset: asset)
generator.appliesPreferredTrackTransform = true          // 竖向锁定，别忘
generator.maximumSize = CGSize(width: maxPixelSize, height: maxPixelSize)
let frame = try await generator.image(at: .zero).image   // iOS 16+ 的 async API（本工程 target 18）
```

要点：
1. **`appliesPreferredTrackTransform = true`** —— 不设会抽出一张横躺的帧（工程竖屏锁定是 90°）
2. `maximumSize` 要给 —— 4K 帧整张解码没必要，缩略图只要 240px
3. 方法是 `async`，调用点 `CameraViewModel.persist(_:)` 本来就是 async，天然好接
4. 保持"**抽不到就静默跳过**"的兜底，别让缩略图失败影响入库（入库已经成功了）
5. 顺手把那条 `debug` 日志换成「视频首帧缩略图已生成」，便于真机核对

**为什么放 2-5a 而不是单独一件**：缩略图就是快门排的左件，
2-5a 的真机截图（四件套版式）天然覆盖它，不值得多开一轮 Mac 往返。

## 六、未决项（开工前需要拍板）

**风格方块的内层画什么？**

原型是 `renderThumb()` 把**同一份成片预览**同时画进相册缩略图与风格方块内层
（`paintPreviewInto($('thumb'))` + `paintPreviewInto($('styleThumbInner'))`），
所以两者**长得一模一样**。

Swift 侧 P4（修图引擎）之前没有渲染链路，只能占位。**建议**：

- 内层 = 该风格**引用的滤镜的 `swatches` 三色**做渐变
  （数据已就绪：`StylePreset.filterId` → `FilterCatalog` 里的 `swatches: [String]`）
- `filterId == nil` 的**纯参数风格**（如 `mood_hongkong_warm_green`）→ 中性深灰渐变兜底
- P4 之后换成真渲染，那时"缩略图与风格方块共用同一套渲染"才真正成立

> 待用户确认。另一种做法是内层直接留空（只保留彩色描边），更贴近"这是入口不是预览"。
