## 零、一句话结论

**功能面板不是底栈里的一行，而是盖住底栏的模态浮层**（原型 `position:absolute; bottom:8px;
left/right:8px; z-index:20`）。这一点与 #6 / #7 的"底栈行"形态完全不同，是本件最容易搞错的地方。
另外：**顶栏第三颗图标要从齿轮换成 ⠿**，并把「设置」收进面板（原「更多」下拉菜单已被该面板取代）。

## 一、位置：模态浮层，不是底栈行

```
                 ┌─ 取景器（可见部分不受面板挤压，面板是"盖"上去的）
底栏 210pt 之上  │
        ┌────────┴─────────────────────────────┐
        │  ⠿ 功能面板（bottom:8 / 左右各 8）      │ ← 盖住整条底栏 + 上方约 30pt
        │  [实况][画幅比][闪光灯][倒计时]         │
        │  [高亮增益][设置][HUD][阶段标记]        │
        │  ─────────────────────────────────   │
        │  简易模式                            › │
        └──────────────────────────────────────┘
```

- 落点：`CameraView.cameraContent` 的 ZStack 里作为一个 **bottom 对齐的 overlay**，
  与底栏栈（VStack）并列，**不参与底栏布局**（不挤压任何行）
- 尺寸：左右内边距 **8**、距屏底 **8**、圆角 **22**、背景 `panel-solid`、
  描边 0.5（`stroke-2`）、投影 `0 18px 44px rgba(0,0,0,.6)`
- 内边距：上 16 / 左右 10 / 下 6
- **净可见账**：面板高约 **242pt**（16 + 网格 162 + foot 约 57.5 + 下内边距 6，Mac 侧以实测为准）
  → 收起态净可见 57% → 面板态 = `778 − 66 − 242 − 8` ≈ **462pt ≈ 59%** ✓ ≥ 50%
  （面板浮在底栏之上，取景器可见部分反而比"底栏行"形态更多）

## 二、折叠 / 展开两态

| 态 | 规格 |
|---|---|
| 折叠（默认） | 不渲染 |
| 展开 | `translateY(112%) → 0`，300ms `cubic-bezier(.22,.9,.3,1)`；opacity `.3 → 1` 260ms |

- **8 个按钮依次浮入**：每个 `opacity 0→1` + `translateY(10px → 0)`，**每个错 40ms**
  （第 n 个延迟 `(n−1)×0.04s`）；**收起时一起退**（无延迟，不拖沓）
  → Swift 侧：每个按钮 `.transition(.opacity.combined(with: .move(edge: .bottom)))` +
  `.animation(.easeOut(duration: 0.24).delay(Double(index) * 0.04), value: isExpanded)`
- **入口**：顶栏第 3 颗图标（⠿）toggle
- **收起出口**（照原型，四处）：
  1. 再点 ⠿
  2. **点取景器任意处**（原型 viewport 的 click 处理器同时做对焦与收起 —— 所以点按对焦时会顺带收面板）
  3. 点底栏控件（原型是全局 `pointerdown` 监听：面板外一律收起）→ Swift 侧在快门、模式条两处 action 里顺带收
  4. 打开设置（面板里那一格自己收）

## 四、互斥关系

| 关系 | 规则 | 原型依据 |
|---|---|---|
| 与滤镜条 / 场景·风格条 / 参数排 | **开面板 → 全部收起**（复用 `collapseOverlays()`） | `if (fnOpen && (ssExpanded \|\| filterExpanded)) collapseAll()` |
| 与 #11 格式选择器 | **互斥**（开一个关另一个） | `fmtChip` click 里 `layout.fnOpen = false`；`btnMore` click 里 `fmtOpen` 同理 |
| 与 ⤢ 放大态 | **不互斥**（面板是独立浮层，放大态照常可开；参数排/图标行让位不影响它） | 原型无 `.zoom-on .fn-panel` 规则 |
| 点面板外 | 收起（含取景器、底栏控件） | 全局 `pointerdown`（`:3026`） |

## 五、⚠️ 需要你拍板的一件事：「阶段标记」那一格

原型第 8 格是**阶段标记**（在 UI 元件上打绿/蓝/黄/橙小点，标出"这个功能属于哪一期"）——
这是**给原型演示看的研发工具**，真机上对拍摄没有价值，而实现它要给每个控件加标记层（成本不低）。

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | 面板做成 **7 格**（第 2 行 3 格，仍按 4 列网格排），去掉阶段标记 | 与原型 8 格版式有一格差异 |
| B | 保留 8 格，第 8 格做成 Swift 版的阶段标记（调试标记，不持久化） | 要给控件加标记层，成本高、收益低 |
| C | 第 8 格换成别的东西（如「水平仪」——原型设置页那个水平指示器；但 CoreMotion 属 B 组，现在只能先记状态） | 需要新增需求定义 |

> 设计说明：面板用**等宽 4 列网格**，7 格时第 2 行留一格空位，视觉上是"左对齐的 3 格"，
> 与原型版式差异不大（截图能直观看出）。请挑一个，或给我第四种想法。

## 七、画幅比遮幅（真功能）的实现要点

- 黑边高度 = `max(0, (视口高 − 视口宽 × 比例) / 2)`，上下各一块，`background: #000`，260ms 过渡
  - 竖拍口径：`4:3 → 4/3`、`16:9 → 16/9`、`1:1 → 1`
- **坐标系**：遮幅与取景器同容器（原型在 `viewport` 内、`z-index:3`、`pointer-events:none`）→
  Swift 侧放进 `previewLayer` 的 ZStack，**叠在网格线与对焦框之上**（黑边区域不该出现网格/对焦框），
  但**不接收触摸**（点黑边区照样对焦，与原型一致）
- ⚠️ 放大态（⤢）下取景器卡片高度会变（300ms 过渡）→ 过渡期间算出来的高度是中间值。
  原型用 `setTimeout(renderFn, 320)` 过渡结束后**重算一遍**；Swift 侧对应做法：
  用 `GeometryReader` 读容器实际高度计算（**天然跟随，不需要延时重算**）
- 边界：实拍裁切（把黑边"烧进"照片）属 B 组；本件只做遮幅示意 + 状态（原型同款）

## 十、风险与回退

| 改动 | 风险 | 回退 |
|---|---|---|
| 顶栏齿轮 → ⠿ | 设置入口变深一层，用户（你）可能一时找不到 | 面板第 6 格就是设置；也可临时在面板外保留一个入口 |
| 面板是模态浮层 | 放大态 / 录制中打开是否合适（录制中面板会挡住录制指示？不会，徽标在取景器顶部） | 面板不参与底栏布局，摘掉 overlay 即回到现状 |
| 画幅比遮幅 | 遮幅高度算错会露出黑边缝 | 高度由 `GeometryReader` 实测算，公式一行；比例为 `4:3` 时与取景器比例相同（本机取景器≈4:3 竖拍）时黑边为 0 ✓ |
| 阶段标记 | 按选项不同风险不同 | —— |

## 十一、Mac 截图 / 真机验收清单

1. 点顶栏 ⠿ → 面板从底部升起（300ms），**8 个圆钮依次浮入**（每个错 40ms，能看出节奏）
2. 面板**盖住整条底栏**（不是挤出一行），取景器可见部分基本不变
3. 点面板里的**画幅比** → 循环 4:3 → 16:9 → 1:1，取景器上下压出黑边（260ms 长出），
   格内文字跟着变（`4:3` / `16:9` / `1:1`）
4. 点**实况** → 圆钮转绿、取景器出现 live 角标（照片模式下）
5. 点**HUD** → 调试浮层真的开关；点**设置** → 打开设置页且**面板自动收起**
6. 点**闪光灯 / 倒计时 / 高亮增益** → 各自有 toast 说明边界（不允许"点了没反应"）
7. **互斥**：先展开场景·风格条，再开面板 → 场景·风格条收起；
   点任何别处（取景器 / 快门 / 模式条）→ 面板收起
8. 点**简易模式**那行 → 置灰外观 + toast 说明（#12 未做）
9. ⤢ 放大态下打开面板 → 照常弹出、不打架
10. 冷启动 → 上次的 画幅比 / 闪光灯 / 倒计时 / HDR / 实况 **状态仍在**（落盘生效）
