## 一、位置：底栈哪一行

**底栈最上方一行，在场景·风格条之上**（原型 `.bottom-stack` 的 DOM 顺序：`row-filter` → `row-scenestyle` → `row-params` → `row-focal` → `row-shutter`）。

Swift 落点：`CameraView.bottomArea` 的 `VStack` **第一个 child**（`Camera/UI/CameraView.swift`）。

```
┌ 滤镜条            ← #7 本件（默认不渲染；上划呼出时占 144pt）
├ 场景·风格条        ← #6（折叠 36 / 展开 147）
├ [参数排 + 图标行]  ← ⤢ 放大态整行让位
├ 焦段条             ← 底栈普通一行（Mac `9129912` 定稿的形态）
└ 快门排
```

**实现方式：条件插入**（`if isFilterStripShown { FilterStripView(...) }`），不是"常驻 + `height: 0`"。

- ⚠️ 为什么不能用 height 0：`VStack` 的 `spacing`（16pt）在 **0 高的子视图上依然生效**，
  会留一条 16pt 幽灵空隙把场景·风格条顶起来。原型是 CSS `height`，没有这个概念，不能照抄。
- 底栈是 bottom-anchored（上方有 `Spacer`），插入一行只会压缩 Spacer，
  **下面的行位置不动** —— 观感就是面板从底栈里升起，与原型 `height 0→144` 同类。

## 二、折叠 / 展开两态

| 态 | 规格 | 实现 |
|---|---|---|
| 折叠（默认） | 完全不渲染，不占任何空间 | `isFilterStripShown == false` → `if` 不成立 |
| 展开 | 整行 **144pt**（原型 `.screen.filter-on .row-filter{ height:144px }`） | `Theme.Size.filterStripExpandedHeight = 144` |

- **144 的依据（原型注释，不是拍的）**：150px 时滤镜展开态净可见只剩 **49.9%**、破 50% 底线；144 → 50.6% ✓
- **呼出（上划取景器）**：几何判定全部照搬原型 `bindSwipe`
  - 起手门槛 24pt（低于它算点按对焦，不算滑动）
  - 位移 ≥ **34pt**、**纵向为主**（`|dx| ≤ |dy|`，否则是在横滑条上滑）
  - 时长 ≤ **0.8s**（长按后拖走不算）
  - 起点必须在取景器**下方 45%** 区域内（原型 `clientY > height × 0.55`）
  - 层级：第一段上划 = 呼出滤镜条 → 第二段上划 = 换呼出场景·风格（原型 `swipeUp` 两级）
- **收起（下划）**：场景·风格展开时 → 全收；只滤镜条展开时 → 收起它（原型 `swipeDown` + `collapseAll`）
- **手势挂载点**：预览层（`previewLayer`）上的 `simultaneousGesture`
  - 用 `simultaneousGesture` 而非 `gesture`：预览层内部是 UIKit 的点按对焦，两者必须并存
  - 挂在预览层而不是整页：底栏是 ZStack 里绘制在上的兄弟视图，
    **从横滑条/药丸/图标行上起手的拖动根本到不了这个手势** ——
    原型靠元素排除清单解决的误触，Swift 侧结构上就不存在
  - 原型第 5 轮的坑（拖完浏览器补 `click`，把刚呼出的浮层立刻收掉）**在这里结构上不存在**
- **面板底**：深色渐变（`rgba(17,19,23,.94) → .82`）+ 顶部 0.5pt 描边（`white .08`）+ 上投影
  （原型 `box-shadow: 0 -10px 30px rgba(0,0,0,.35)`）。没有这层底，标题字压在取景画面上会发虚。

## 三、14 款滤镜卡的布局

```
┌ 面板（内插 14） ────────────────────────────────────────┐
│ 滤镜 · 只叠颜色层（再点一次取消）              冷青暖橙  │ ← 标题行 14pt，右端 = 当前滤镜名（nil → 「无」）
│                    ↓ 间距 9                             │
│ [缩略面 84×84] [缩略面] [缩略面] …（横向滚动 14 张）      │
│   柔暖胶片        浓暖胶片        纪实冷调               │ ← 名字 10pt，行高钉死 11
└────────────────────────────────────────────────────────┘
```

| 项 | 值 | 出处 |
|---|---|---|
| 卡宽 / 缩略面 | **84×84**，圆角 **12** | 原型 `.filter-swatch` |
| 卡内间距 | **4**（缩略面 ↔ 名字） | 原型 `.filter-card{ gap:4px }` |
| 名字 | **10pt**，**行高钉死 11pt**，单行截断 | 原型 `.filter-name`；钉死理由同 `styleNameHeight`（深度账不许浮） |
| 卡间距 / 条左右内边距 | **8 / 14** | 原型 `.strip` |
| 面板顶部内边距 | **7** | 原型 `.row-filter .ss-block-title{ padding-top:7px }` |
| 横滑 | `ScrollView(.horizontal)`，隐藏指示器 | 与场景/风格条同构 |

**缩略面画什么（P4 之前的占位，规格已明确）**：该滤镜自己的 `swatches` 三色渐变（线性，左上→右下）。
- 原型卡 = **实时取景缩略图**（当前画面套该滤镜），P4 有渲染链路后再换；
- hex 解析**复用 `StyleThumbnailView.color(from:)`**（该方法与 `fallbackColors` 由 private 放开为 internal，
  仅访问级别改动，全工程只有一份解析）；`swatches` 不足两色 → 中性灰兜底。
- 换真渲染时**只改 `FilterStripView.swatchFace` 一处**，调用点不动。

**选中 / 取消**：

| 态 | 缩略面 | 名字 |
|---|---|---|
| 未选中 | 1pt 描边 `white .12` | `secondaryText` |
| 选中 | **2pt 白描边 + 白泛光**（`0 0 16px rgba(255,255,255,.28)`） | **白 + semibold** |
| 已选中再点 | 回到未选中、`filterId = nil`（原片） | toast「已取消滤镜，回到原片」 |

> 注意：滤镜选中态是**白**描边，不是风格卡的 accent —— 原型的 `.filter-card.on` 就是这么写的，
> 刻意保留这个差异（滤镜是"叠加层"，风格是"成片方案"）。

**内容深度账**（自检第 7 组按同批令牌复算）：
`顶内边距 7 + 标题 14 + 间距 9 + 卡 84 + 卡内距 4 + 名字 11 = 129 ≤ 144`，**余 15pt**。

## 四、与 #6（场景/风格条）的互斥

**双向互斥，原型 `setFilter` / `setSS` 原样**：

| 动作 | 结果 |
|---|---|
| 上划呼出滤镜条 | 场景·风格条**收起为折叠胶囊**（36pt，**不隐藏** —— 原型 CSS 只把 `ssExpanded` 置 false） |
| 展开场景·风格条（胶囊 / 箭头 / 风格方块三入口任一） | 滤镜条**收起** |
| ⤢ 放大态 | 滤镜条**强制隐藏**（原型 `.screen.zoom-on .row-filter{height:0}`），**状态保留**、退出放大态即恢复 |

- 落点：`CameraViewModel.toggleSceneStyle()`（补 `isFilterStripExpanded = false`）、
  `CameraViewModel.swiped(up:)`（呼出滤镜条时 `isSceneStyleExpanded = false`）
- 自检有专门一条**反向覆盖**：少做任何一边都会出现"两个扩展浮层同时展开"把净可见压破 50%

## 五、与焦段条的互斥

| 情形 | 焦段条 | 依据 |
|---|---|---|
| 滤镜条展开 | **整行收起** | 原型 `.screen.filter-on .row-focal{ height:0; opacity:0 }` |
| ⤢ 放大态（滤镜条已隐藏） | **照常显示**，落进取景器卡片内底边 | 原型 `.zoom-on` 保留焦段条；Swift 侧是Mac `9129912` 定的"底栈普通一行"形态 |

落点：`CameraView` 里焦段条的条件 = `!viewModel.isSceneStyleExpanded && !isFilterStripShown`。
（`isFilterStripShown = isFilterStripExpanded && !isZoomOn`，所以放大态下滤镜条"不算展开"，焦段条不被误收。）

## 六、状态持久化

| 状态 | 存哪 | 说明 |
|---|---|---|
| `filterId` | **UserDefaults** `lumen.camera.filter`（#6 引入，已可用） | `nil` = 无滤镜 / 原片；`didSet` 自动落盘 |
| `isFilterStripExpanded` | **不落盘** | 拍摄时的临时手势状态，原型 `layout.filterExpanded` 也不进「保留设置」 |

**两条单向规则**（原型注释同款，别改成双向）：
- **选滤镜不清风格** —— 滤镜是叠加层，可以在风格之上再叠
- **选风格把滤镜重置为「无」** —— 两层胶片叠加会出脏色（已由 #6 落地并验证 ×2）

「保留设置」里"是否记住滤镜"属模块 #12（现在三项一律记住）。

## 八、本件的诚实边界

1. **滤镜对画面的实际作用在 P4**：本件交付"选择状态 + UI"。呼出时 toast 说明，不假装画面已经变了。
2. **与参数排的互斥尚未建**（`#6` 遗留、`#8` 补齐）：规格里"展开任一浮层时收起参数刻度条 / EV 圆盘"
   需要那些组件先存在 —— 现在参数排只有 EV 一列竖滑块，展开浮层时**照旧显示**。
   已记进 `CONTEXT_HOT.md` Backlog ④ 与 `docs/07` 跨阶段待办。
3. **简易模式下"浮层保持隐藏"的手势分支未做**：Swift 侧还没有简易模式（模块 #12）。
4. **面板圆角刻意偏离原型一处**：原型面板贴屏边（顶角 18、底角 0，往下连着整条底栈）；
   Swift 侧底栈整体内缩 16pt（既有版式），悬空时底角留方像被切 → 四角统一取 18，读作"浮起的卡"。

## 九、Mac 截图验收清单（#7）

1. 上划取景器 → 滤镜条升起，**14 张卡**横滑，卡下名字完整不截断
2. 点一张卡 → **白描边 + 白泛光**、名字转白；标题行右端显示该滤镜名
3. **再点同一张** → 取消，标题行回「无」，无描边
4. 呼出滤镜条时 → **场景·风格条收成折叠胶囊**、**焦段条整行消失**
5. 下划 → 滤镜条收起；再上划一次 → 换成场景·风格条展开（两级手势）
6. ⤢ 放大态 → 滤镜条隐藏、焦段条还在卡片内底边；退出放大态滤镜条状态恢复
7. 点按取景器 → 对焦框照常出现（手势没吞掉点按对焦）
8. 冷启动 → 上次选的滤镜名仍显示（落盘生效）
