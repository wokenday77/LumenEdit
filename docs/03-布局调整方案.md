### ⚠️ 有一条它被评测明确点名的毛病，我不重复

评测原文意思是：**对焦和曝光补偿用了圆环滑条，另外三个参数用了横向滑条，这种交互上的不统一让人困惑。**

所以我的设计里有一条硬约束：**所有参数滑块只用一种形态**（横向或竖向，二选一，全局统一），不做圆环混排。这是能直接从别人的产品里学到的教训，没理由再踩一次。

### 骨架映射到 LumenEdit

| 飓风相机 | LumenEdit | 说明 |
|---|---|---|
| 底部右侧 = LUT 按钮 | 底部右侧 = **场景 / 风格入口** | 它的核心是 LUT 调色，我们的核心是「选场景直接拍」，所以这个位置放场景风格 |
| 参数滑块排在取景窗口底部 | 同样放取景窗口底部 | 完全采纳，但形态统一 |
| 上划呼出隐藏模块 | 上划呼出滤镜条 + 完整参数 | 完全采纳 |
| 简易模式开关 | 同样有，但保留「场景」 | 场景是我们的主线，不能砍 |

## 1. 设计原则

1. **取景器是全屏底图，占 100% 面积。** 所有控件都是**叠在它上面的浮层**，不再是"上下各占一条、把取景器挤成一块矩形"。这是本方案最根本的一条改动。
2. **浮层只遮挡，不挤压。** 任何面板展开都不会改变取景器的尺寸——它只是暂时遮住下半部分。所以调整面板时构图不会跳。
3. **常驻浮层越少越好，且越靠边越好。** 常驻的只有：顶部控制行、场景风格胶囊行、参数排、快门排。
4. **场景 / 风格 > 参数 > 其他。** 视觉权重按这条排，不平均用力。

### 占比结论

- 常态：取景器从 **46.0% → 59.7%**（相对提升 30%）
- 参数收起：**66.8%**
- 简易模式：**72.0%**（相对提升 57%）

而且更重要的不是数字，是**性质变了**：取景器不再是"夹在两条带子中间的矩形"，而是**无边界的全屏画面**，控件浮在它上面。这才是相机 App 该有的观感。

## 3. 各区域详细设计

### 3.1 顶部控制行（44px · 浮层 · 常驻）

从左到右：
1. **模式胶囊**：照片 / Live / 视频（视频置灰带锁）
2. **EV 数值胶囊**：实时的 `+0.3`，点它归零
3. 弹性间距
4. **设置图标**（齿轮，低对比）
5. **调试浮层开关**（仅开发期显示）

底部加 120px 高的渐隐黑（scrim）保证白色文字在亮天空下也可读。scrim 不算"遮挡"，因为它只是让文字可读，画面本身仍可见。

### 3.2 取景器（全屏 · 底层）

- 铺满整个屏幕，圆角由屏幕本身提供
- 叠加物：三分构图线（可关）、对焦方框、对焦锁定提示
- 点击任意位置 → 对焦 + **同时收回所有已展开的浮层**（这是 iOS 相机的常规行为，不冲突：对焦是即时的，收回只是视觉收拢）

### 3.3 场景 · 风格行（浮层 · 可折叠 · 位于参数排之上）

**折叠态（默认，36px）**：一条胶囊，显示当前选中项，带缩略预览色块

```
[ 场景 ▸ 人像 ]  [ 风格 ▸ 柔暖人像 ]                    ⌃
```

**展开态（144px）**：变成两条真正的横滑条（场景条 34 + 风格条 84 + 各 13px 标题）

- **场景条**排在**风格条之上**——因为"选场景直接拍"是产品主线，视觉上必须更靠中心
- 风格卡保持：缩略图 + 名称 + 参数徽标
- 展开时浮层用半透明（alpha 0.82）+ 静态背景色，**不用实时毛玻璃**（理由见 §5）

### 3.4 参数排（浮层 · 可收起 · 常驻底部第一行）

**平铺态（104px，默认）**：四列竖向滑块，每列 = 标签 + 竖向轨道 + 当前值

| EV | ISO | 快门 | 白平衡 |
|---|---|---|---|
| 竖向滑块 | 竖向滑块 | 竖向滑块 | 竖向滑块 |
| +0.3 | 自动 | 1/125s | 5600K |

P2 之后参数会超过 4 个（加色温 / 色调 / 锐化 / 降噪…）→ **左右分页**，底部加 2~3 个小圆点指示。每页 4 列。

**收起态（44px）**：一行四个数值（仪表条），像仪表盘一眼看全，点任意处展开。

**为什么竖向而不是横向**：横向滑块一行只能放 1~2 个参数，四列横向滑块要占 4 行 = 200px+。竖向 4 列只占 104px，且拇指在小屏上更容易精准拖动。

### 3.5 快门排（浮层 · 常驻 · 最底一行，92px）

```
[ 相册缩略图 ]        ● 快门        [ 场景·风格 ]
```

- 左：相册缩略图（显示当前成片效果）
- 中：快门（全屏最大元素，**60pt**；2026-09-16 由 66pt 微缩，行高不变）
- 右：**场景·风格入口**（对位飓风相机的 LUT 按钮位置，但换成我们的主线功能）

> 「镜头切换」圆钮已于 2026-09-16 移除 —— 它与底部 7 图标行的「前置」功能重复，只保留后者一个入口。

### 3.6 对焦圆盘（浮层 · **模态** · 2026-09-16 定稿）

点底部图标行的「对焦」展开。它是**模态浮层**，规则与常驻浮层不同。

**尺寸与位置**

| 项 | 值 |
|---|---|
| 直径 | `--fd-size: **280px**`（唯一可调旋钮，定义在 `:root`） |
| 水平 | **居中**（不学参考图的"圆心贴左边缘、左半被裁"） |
| 垂直 | 自屏幕底向上依次：底部安全区 `--fd-pad:18px` → 开关行 `--fd-auto-h:29px` → 间距 `--fd-gap:12px` → 圆盘 280px |
| 结构 | `.fd-wrap` 竖排 flex：圆盘在上、开关行在下。**开关是布局上的下一个 flex 项 → 物理上不可能压圆盘**，圆盘挪动时开关自动跟随 |

**圆盘本体**

| 项 | 值 |
|---|---|
| 刻度弧 | **右半圈**：0.0 正下 → 0.5 正右 → 1.0 正上；`focusAngle(v) = 180 − 180v`（CSS 角，0° = 12 点方向） |
| 刻度 | **51 格三层**：主 11（长 32）/ 中 20（长 20）/ 副 20（长 12）；描边 2.4 / 1.7 / 1.1；高亮段（当前值 ±0.06）单独一层 `#00E08A` + 外发光 |
| 数字 | 0.0~1.0 共 **11 个**，径向排布；`FD_NUM_FLIP = 180` —— 每个数字的"上"指向圆心，**因此顶部数字是倒的**（径向排布的正常表现，专业相机 App 常见做法） |
| 中心图标 | 「◎ 对焦」，位于圆盘**几何正中心** |
| 指针 | 绿色三角，**尖端朝圆心**，贴刻度环外缘，带 `drop-shadow` 发光 |
| 数值框 | 圆盘**内**右侧，偏移 `calc(var(--fd-size) * 0.20)`（按比例，不用死值）；绿框 + 绿色等宽数字；值 ≥0.995 显示 `∞` |
| 底色 | 深色半透明 radial-gradient（.78 / .84 / .88），能透出取景画面 |
| 配色 | 深底 + 白刻度 + `#00E08A` 高亮 |

**打开时的行为**

- 底部浮层栈**整条收起**：`.screen.dial-on .bottom-stack{display:none}`（滤镜条 / 场景风格 / 参数排 / 焦段条 / 快门排一并不显示），底部只剩「自动对焦」开关行 —— 与参考图一致
- 出口：**点屏幕任意处关闭**（排除圆盘内部与「对焦」图标本身）

**为什么是 280px，而不是参考图的尺寸**

参考图实测（照片有透视畸变，±10% 误差）：直径约屏宽 **58%**、占屏高约 **23%**，**圆心贴在屏幕左边缘、左半圆被裁掉**。

- 「完整露出」要求圆心两侧都留出半径空间 → 若同时要「数值框在圆盘**外侧**」，上限只有 **224px**
- **372px**（屏内宽上限）比参考图大 1.7 倍，形态差距明显
- **216px + 贴左边缘**（严格对齐参考图比例）会违反「完整露出」，且数值框没地方放
- → **280px 居中**是折中：完整露出 ＋ 数值框在右侧 ＋ 视觉最接近参考图

**自检底线（`tools/check_prototype.js` 第 7 组）**

- 圆盘直径 **≤ 屏内宽 372px**（否则会被裁，"完整露出"不成立）
- 圆盘打开时净可见取景面积 **≥ 30%** —— 模态操作，与常驻浮层的 50% 底线**分开**；30% 用于防"圆盘占满屏幕"

**两个踩过的坑（不要再犯）**

1. **半径脱节**：曾出现"圆盘 340px、刻度半径却是 224px"→ 刻度全跑到盘外，还被底部 UI 压住。现在**所有半径写在 SVG 的 400 坐标系里、随 `viewBox` 等比缩放**，改 `--fd-size` 一处即可，结构上不可能再脱节。
2. **角度基准混用**：CSS `rotate` 的 0° 在"上"、`cos/sin` 的 0° 在"右"，差 90°，混用必然错位。现在**刻度 / 数字 / 高亮段 / 指针 / 拖动反解全部只吃 `focusAngle()` 一个函数**。

## 4. 功能模块的呼出与收回

| 目标 | 呼出方式 | 收回方式 |
|---|---|---|
| 场景 / 风格完整横滑条 | 点胶囊行右侧箭头　/　点底部右侧「场景风格」按钮 | 点箭头　/　点取景器 |
| 滤镜条 | **取景器下缘上划**　/　点快门排左侧的滤镜小按钮 | 下划　/　点取景器 |
| 完整参数（P2 起 8 项） | 点参数仪表条　/　**再次上划** | 点收起箭头　/　点取景器 |
| 全部收回 | — | 点取景器任意处　/　下划 |

**上划的层级顺序**：第一次上划 → 滤镜条；第二次上划 → 完整参数。理由是滤镜比参数高频得多。

**遮挡上限（硬约束）**：浮层总高**不超过屏高 28%（236px）**。超过部分改为浮层内部滚动。这样任何时候构图区都不会低于 50%——**滤镜看着好看但看不到构图，是最糟的体验**。

## 5. 简易模式的取舍

### 保留

| 项 | 理由 |
|---|---|
| 全屏取景器 + 点按对焦 | 这是相机，不能砍 |
| 快门 + 相册缩略图 | 同上 |
| 顶部：模式胶囊 + EV 数值 | 模式切换是必需；EV 数值只读展示，告诉用户当前曝光状态 |
| **场景条（单行，常驻）** | **产品主线，必须留**。简易模式下"选个场景直接拍"就是全部体验 |

### 隐藏

| 项 | 收到哪里 |
|---|---|
| 参数排（整条） | 完全隐藏 |
| 滤镜条及其入口 | 完全隐藏 |
| 风格条 | 隐藏（场景与风格二选一，保留场景） |
| 设置入口 | 移到长按取景器呼出 |
| 调试浮层 | 默认关闭 |

净可见取景区 **608px · 72.0%**。

### ⚠️ 我对这条设计有异议，提出来你定

**简易模式完全不显示 EV 滑块，我认为有风险。** 理由：拍摄时最高频、最需要临场调整的就是曝光补偿（逆光人脸发黑、夜景过曝）。如果简易模式里连 EV 都调不了，用户只能退出简易模式才能救回一张照片，那这个模式的实用性会打折扣。

**我的建议**：简易模式保留**一条横向 EV 滑块**（52px）。
- 净可见变成 556px · **65.9%**
- 仍然显著好于常态的 59.7%
- 仍然满足"只保留取景器、快门、场景"的极简意图（EV 只是一条细线，视觉上几乎不占份量）

**这条我按你的决定执行**——你说严格按原方案（不含 EV），我就按 72.0% 那版做。

## 6. 保持差异化：视觉权重的分配

飓风相机的核心是 LUT 调色，但它的 LUT 按钮只是个普通图标按钮，参数滑块反而在取景窗口底部占了最大一块。**我们不这么排。**

| 层级 | 元素 | 手法 |
|---|---|---|
| **一级（最重）** | 场景、风格 | **实心强调色胶囊**（选中态填充 accent）／风格卡带缩略图预览；位置在参数排**之上**，更靠视觉中心 |
| 二级 | 快门 | 屏幕最大元素（66pt），纯白高对比 |
| 三级 | 参数 | **低对比**：灰色细轨道 + 小字标签，不抢视线 |
| 四级 | 设置、调试、格式 | 图标按钮，低不透明度 |

结论一句话：**用户第一眼看到的应该是「场景」和「风格」，不是一堆滑块。** 滑块是给进阶用户微调用的，不该占据视觉主位。

## 7. iOS 实现要点（含对 P1a 的一处修正）

### 7.1 取景器全屏 + 浮层坐标系的解法（修正 P1a 的妥协）

P1a 里我为了避免对焦方框坐标错位，让取景器只占安全区、上下留黑边。**现在有更好的解法**——`.ignoresSafeArea()` 只影响加在哪个子视图上：

```swift
ZStack {
    PreviewView(...)                       // 铺满全屏
        .ignoresSafeArea()
    FocusIndicatorView(...)                // 与预览同一坐标系 → 对焦方框 1:1 映射，不会偏
        .ignoresSafeArea()
    ControlOverlay()                       // 不 ignore → 自动避开灵动岛与 Home 指示条
}
```

预览与対焦框都 ignore → 共享同一个全屏坐标系；控制浮层不 ignore → 不用手写任何 inset 数字。**两边的坐标系各自正确，这就是正解。**

### 7.2 上划手势的冲突（必须只挂在下缘热区）

取景器全屏后，点按对焦（单击）和上划呼出会互相干扰。对策：

- 上划手势**只挂在取景器下缘 44pt 高的透明热区**上，不要挂在整个取景器
- 用 `.simultaneousGesture(DragGesture())` 而不是 `.gesture()`，避免它吃掉单击
- 热区高度 44pt 是拇指自然落点，且不影响中上部构图区的点按对焦

### 7.3 浮层展开动画不要挤压取景器

用高度约束 + `withAnimation(.spring(response: 0.32, dampingFraction: 0.86))`。
**不要**用 `.transition(.move)` 配合条件插入/移除——那样在动画期间取景器会被压缩，画面会"跳一下"，这是浮层改成 overlay 之后最容易犯的错。

### 7.4 状态持久化（UserDefaults）

- 参数排是否收起
- 是否简易模式
- 上次选中的场景 / 风格 / 滤镜
- 三分构图线开关

冷启动恢复，别让用户每次重设。

### 7.5 ⚠️ 毛玻璃的性能代价（需要真机实测）

`\.ultraThinMaterial` 效果最好看，但它会**对取景画面做实时模糊**——AVCaptureVideoPreviewLayer 是每秒 30~60 帧持续输出的，等于每帧都要多算一次大半径模糊。这在 iPhone 上不是小事，可能明显掉帧、发热。

**我的做法**：浮层先用**静态半透明色**（alpha 0.82 + 0.5px 描边），把毛玻璃做成一个可切换项放进调试浮层。真机测过帧率之后再决定默认值。**不先上毛玻璃，避免一开始就掉帧还不知道为什么。**

### 7.6 触觉补充

已有：滑块刻度、模式切换、快门、对焦。
新增：浮层展开 / 收起 → `UIImpactFeedbackGenerator(style: .light)`，给"面板弹出来"一个物理确认。
