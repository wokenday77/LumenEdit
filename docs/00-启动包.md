## 三、工程纪律（8 条 · 摘自 `docs/04`，完整版读那份）

1. **分层**：UI（View/VM）不碰设备；设备一切写操作只走 `CaptureDeviceConfigurator`
2. **唯一锁**：`beginConfiguration` / `lockForConfiguration` 只在 configurator（自检会拦）
3. **事件驱动不轮询**：硬件变化由会话 `@Published` 主动发布；例外只有每秒 `refreshSnapshot()`（只写日志）
4. **单一真源**：预设数据（滤镜/风格/场景/焦段/格式/**刻度条**）以原型为真源，`check_presets.js` 逐条比对
5. **浮层互斥逐点接线**：新增浮层必须同时进 `collapseOverlays()` 与 `dismissTransientPopovers()`，且**展开者自己不能调后者**
6. **push 纪律**：先 `git fetch` → **合并用 `git merge FETCH_HEAD`，绝不强推**；`git add` 按路径列出（**禁 `-A`**）；
   通道先试"清空代理变量直连"，失败再走加速器 `-c http.proxy=…`（端口动态，**别 --global**）
7. **节奏**：先出方案 → 用户确认 → 再写代码；做完一步汇报产出与遗留，等确认再下一步
8. **每件交付都要有自检 + 变异测试**：新守卫必须"注入坏数据"验证真会报错，并跑一次未变异对照组

**双机协作**：WB 改 Swift + 自检；**CB / Mac** 改 `prototype/index.html`（**WB 只读不写**）、编译、真机验证、`[mac-fix]`。

## 四、长期记忆里的关键坑（都是真踩过的）

1. 🔴 **Swift `catch` 不到 ObjC 异常** —— 只能在"入参是否合法"上防；读硬件状态的 API 先问"它此刻处于有效状态吗"（`startRunning()` 异步）
2. 🔴 **`let` 带默认值的属性不进 memberwise init** —— 配置字段要用 `var`（否则传参报 "extra argument"，编译才暴露）
3. 🔴 **`AVCaptureDevice` 不暴露镜头绝对焦距** —— 别用 mm 相除，按**镜头角色**读设备（`virtualDeviceSwitchOverVideoZoomFactors` + 原生阶梯）
4. 🔴 **自检守卫的作用域**：断言"某函数里必须有 X"要用 **`methodBodyOf` 切方法体**（全文匹配会被别处同类代码满足=假绿）；**比对顺序前先剥 `//` 注释**（注释里提到目标词会假 FAIL，批六又踩一次：视图注释里留着"hasSubTicks 已删"的说明）
5. 🔴 **两条检查脚本会"打架"** —— 断言语义跨两个文件时，只能放**两边都读**的脚本里
6. 🔴 **镜像/同步整目录 + 固定五步**：① D: fetch+merge → ② D:→工作区 → ③ 改 → ④ 工作区→D: → ⑤ add/commit/push。
   硬编码文件清单会**静默少同步**；顺序颠倒会覆盖别人的改动
7. 🔴 **几何账要写成可执行的检查**（读令牌 + 逐机型复算），文档只贴脚本打印的数字（手算表已两次漏项，各乐观 8.5pp）
8. **2pt 余量 = 危险信号**；中文字宽按 1.0em 推、拉丁/数字必须实测（批六实测对象：40pt 档距下 5 位数+K 的 WB 标签估算 ≈39pt）；SF Symbol 名写错静默留白（小图形用 `Path` 自画）
9. 🔴 **能力探测 API 要"与将要执行的那次写入"逐字对应**（2026-09-19 白平衡 7 连崩）：
   `isWhiteBalanceModeSupported(.locked)` / `isFocusModeSupported(.locked)` 在虚拟多摄上**误报 true**
   （SDK `AVCaptureDevice.h:538-541` 只允许锁 Current）→ 写计算值抛 ObjC 异常 abort。正确：`isLockingWhiteBalanceWithCustomDeviceGainsSupported`（:1601）/ `isLockingFocusWithCustomLensPositionSupported`（:1110）
10. 🔴 **硬件状态回读 ≠ 用户意图**（B3b 复验 ③ 死锁）：`.autoFocus` 对焦一次后**系统自动转 `.locked`**
    → 按 `focusMode == .locked` 推断"用户锁了手动对焦"会死锁成永久"仅测光"。**判据：能被系统改写的状态
    只能当"读数"喂 UI，档位必须由用户操作路径显式记录**（⑱ 守写入点唯一）；同族：**推断值要守卫，显式值不守卫**
11. 🔴 **设备对象**是"实例级"状态容器 —— 复用/换设备都会带出 `.custom` / `.locked` 残留（2026-09-20 实锤 A）：
    `exposureMode` / `whiteBalanceMode` 只会被**当前挂着的那台设备**改写，`removeInput`/`addInput` 都**不重置**它。
    **判据：跨设备搬运 = 先归一（`normalizeToAutoLocked`），再重放；永远不要假设新设备的档位是干净的。**
12. 🔴 **形态切换的转场边界按"用户视角"分类**（2026-09-20 用户要求 ③）：**只有点焦段档位**该看到转场（≤1s）；
    切手动 / 开对焦盘 / 切模式 / App 回切全走**静默**（`applyFocalTargetSilently` 不置 `isLensSwitching`）。
    ⚠️ 入口动作挂 **`form` 边沿**（挂 `isLensSwitching` 边沿 → 静默路径"点了没反应"）；静默省的是"模糊"不是"耗时"（换 input 固有 0.6~0.75s 停顿仍在）
13. 🔴 **对焦读数 0.00 是"最近端 / 未收敛"，不是可锁的"当前值"**（2026-09-20 问题 4）：
    锁上去焦点死在最近端、点按全走"仅测光"**无出路**。判据：**推断值要守卫，用户显式给的值不守卫**
    ——"关自动对焦"是推断 → 读数必须 `finite && > 0.01` 否则拒绝 + toast；圆盘**显式**拖到 0.00 是真实意图 → 照写
14. 🔴 **`commitConfiguration()` 返回 ≠ 系统已完成工作**（批五 · 真凶级）：切模式/换设备会让会话**重新协商
    `activeFormat`**，落地**晚于**我们的重放，把 `.custom`/`.locked` 清成自动。**判据：凡"改完会话配置 →
    立刻按意图写设备参数"的地方都要有"延迟复查 + 被清就补写"层**（`reverifyManualIntent` 四拍；
    补写前先核对**已发布的意图态**，用户中途点回自动就**不能**按回去）
15. 🔴 **等异步任务用"回执"，不要"盲等超时"**（批五）：盲等分不清"慢"与"没做"。
    ⚠️ **"已经满足"必须单独一个回执**（预切换抢先完成时 `form` 不再变化 → 排队动作永不执行 = "点了没反应"）
16. 🔴 **工具坑**：同一文件**并行编辑会丢写入** + **`old_string` 带尾换行而 `new_string` 不带会吞掉下一行换行**
    （`const` 并进 `//` 注释 → 守卫变量未定义）⇒ 同文件编辑**串行发**，改完 `git diff --stat` + grep 关键符号核对；
    编辑注释行后**重读现场或直接跑脚本**
17. 🔴 **点按对焦会顶掉手动曝光**（2026-09-21 批六 ③ · 系统语义）：
    `setFocusAndExposurePoint` 把 `exposureMode` 设成 `.continuousAutoExposure` → 手动 ISO/快门被顶掉
    （实测日志链：`11:45:10.006 手动 799/1/60 → 13.242 点按对焦 → 16.329「曝光=自动」`）。
    **判据：点按只是"重新对焦"，不是退出曝光手动的意图 —— 点按前取意图快照、点按后按快照重放**
    （曝光/白平衡/EV 同理；"仅测光"路径 `setExposurePointOnly` 自带 `.custom` 守卫不用管）；
    顺序：先写回 `.custom` **再**推 EV（`applyExposureBias` 见 `.custom` 会回切自动）
18. 🔴 **掉帧排查判据 = 重启 App 能不能立刻恢复**（2026-09-21 批六 ④ · Mac CB 初判）：
    热降频/系统节流不会因重启 App 快速恢复；App 侧泄漏（模式切换 / 静默预切换没拆净的 input/output）会随次数累积、
    重启清零。**做法：input/output 增删逐点埋计数（漏埋=计数错，比没有更坏）+ 活数超出该模式预期即 WARN +
    内存 `phys_footprint` + 每次切换耗时 + 5s 周期日志**；若只在长时间使用后出现且重启不能恢复 → 转发热/系统线
19. 🔴 **`git` 自写的 ref 在本机会静默丢失**（可复现）：**`refs/` 子目录下的 ref 每次必丢**，连带
    **`refs/remotes/origin/` 整个目录**都会被删（`merge --ff-only` 报 Fast-forward、reflog 也记了，文件却没了）→
    **判远端只认 `git ls-remote`**（`.git/FETCH_HEAD` 可能是**过期残留**）。**2026-09-22 补三条实战**：
    ① **refs 一定要"最后"写** —— 写完只跑**只读**命令（`log`/`status`/`rev-list` 安全），**任何写操作
    （commit/merge/reset/fetch/push）都会再把它清掉**；② HEAD 已被清到不可解析时（`git status` 全仓显示成
    `A`、`rev-parse HEAD` 打印字面 `HEAD`），**`git push origin <sha>:refs/heads/main` 可按 SHA 直推**（绕开
    本地 ref，最稳）；③ push 成功后还要 `ls-remote` 复核 + 重写本地三个 ref（`makedirs` 逐级建目录），
    ⚠️ 别在 push 失败时按"远端旧值"写 ref（会把本地 ref 写回旧 tip，我犯过一次）。
20. 🔴 **"删一大块代码后扫悬空引用"不能靠手工列关键词表**（2026-09-22 编译错实锤）：删"设备级预热"时按手工
   清单扫残留，**清单恰好漏了 `interruptionObserverRegistered`** → 声明被删、引用还在 → Mac 编译
   `cannot find in scope`，而当时 `check_swift` **全过**（它的"状态引用完整性"只查跨文件的 `viewModel.*`/`env.*`）。
   **做法：靠结构性守卫**——`check_swift` 新增 **o8（成员引用完整性）**：织"已声明白名单"后比对"裸赋值 `X = …`"
   与"`guard !X`"里的裸标识符，不在白名单即 FAIL 并打印 **行号:符号**；配 `M-o8a/M-o8b` 变异。
   → **下次删任何属性/方法块：先跑 `check_swift`，让 o8 点行号，别再列关键词。**
21. 🟠 **两个"看着像 bug"的验证坑（都踩过）**：① **武装（启动参数）后手点 App 图标** = 无参启动顶掉参数
   （症状"注入了没反应"）⇒ 只能远程拉起；② **1.33pt 细刻度叠亮取景画面上不显眼** ⇒ 别急着判"没渲染"，先采样像素。
