## 三、工程纪律（8 条 · 摘自 `docs/04`，完整版读那份）

1. **分层**：UI（View/VM）不碰设备；设备一切写操作只走 `CaptureDeviceConfigurator`
2. **唯一锁**：`beginConfiguration` / `lockForConfiguration` 只在 configurator（自检会拦）
3. **事件驱动不轮询**：硬件变化由会话 `@Published` 主动发布；例外只有每秒 `refreshSnapshot()`（只写日志）
4. **单一真源**：预设数据（滤镜/风格/场景/焦段/格式/**刻度条**）以原型为真源，`check_presets.js` 逐条比对
5. **浮层互斥逐点接线**：新增浮层必须同时进 `collapseOverlays()` 与 `dismissTransientPopovers()`，且**展开者自己不能调后者**
6. **push 纪律**：先 `git fetch` → **合并用 `git merge FETCH_HEAD`，绝不强推**；`git add` 按路径列出（**禁 `-A`**）；
   通道先试"清空代理变量直连"，失败再走加速器 `-c http.proxy=…`（端口动态，**别 --global**）
7. **节奏**：先出方案 → 用户确认 → 再写代码；做完一步汇报产出与遗留，等确认再下一步
8. **每件交付都要有自检 + 变异测试**：新守卫必须"注入坏数据"验证真会报错，并跑一次未变异对照组

**双机协作**：WB 改 Swift + 自检；**CB / Mac** 改 `prototype/index.html`（**WB 只读不写**）、编译、真机验证、`[mac-fix]`。

## 四、长期记忆里的关键坑（都是真踩过的）

1. 🔴 **Swift `catch` 不到 ObjC 异常** —— 只能在"入参是否合法"上防；读硬件状态的 API 先问"它此刻处于有效状态吗"（`startRunning()` 异步）
2. 🔴 **`let` 带默认值的属性不进 memberwise init** —— 配置字段要用 `var`（否则传参报 "extra argument"，编译才暴露）
3. 🔴 **`AVCaptureDevice` 不暴露镜头绝对焦距** —— 别用 mm 相除，按**镜头角色**读设备（`virtualDeviceSwitchOverVideoZoomFactors` + 原生阶梯）
4. 🔴 **自检守卫的作用域**：断言"某函数里必须有 X"要用 **`methodBodyOf` 切方法体**（全文匹配会被别处同类代码满足=假绿）；**字符窗口**会被注释挤爆=假红；**比对顺序前先剥 `//` 注释**（注释里提到目标词会假 FAIL，本轮又踩一次）
5. 🔴 **两条检查脚本会"打架"** —— 断言语义跨两个文件时，只能放**两边都读**的脚本里
6. 🔴 **镜像/同步整目录 + 固定五步**：① D: fetch+merge → ② D:→工作区 → ③ 改 → ④ 工作区→D: → ⑤ add/commit/push。
   硬编码文件清单会**静默少同步**；顺序颠倒会覆盖别人的改动
7. 🔴 **几何账要写成可执行的检查**（读令牌 + 逐机型复算），文档只贴脚本打印的数字（手算表已两次漏项，各乐观 8.5pp）
8. **2pt 余量 = 危险信号**；中文字宽按 1.0em 推、拉丁/数字必须实测；SF Symbol 名写错静默留白（小图形用 `Path` 自画）
9. 🔴 **能力探测 API 要"与将要执行的那次写入"逐字对应**（2026-09-19 白平衡 7 连崩）：
   `isWhiteBalanceModeSupported(.locked)` / `isFocusModeSupported(.locked)` 在虚拟多摄上**误报 true**
   （SDK `AVCaptureDevice.h:538-541` 只允许锁 Current）→ 写计算值抛 ObjC 异常 abort。正确：`isLockingWhiteBalanceWithCustomDeviceGainsSupported`（:1601）/ `isLockingFocusWithCustomLensPositionSupported`（:1110）
10. 🔴 **硬件状态回读 ≠ 用户意图**（B3b 复验 ③ 死锁）：`.autoFocus` 对焦一次后**系统自动转 `.locked`**
    → 按 `focusMode == .locked` 推断"用户锁了手动对焦"会死锁成永久"仅测光"。**判据：能被系统改写的状态
    只能当"读数"喂 UI，档位必须由用户操作路径显式记录**（⑱ 守写入点唯一）；同族：**推断值要守卫，显式值不守卫**
11. 🔴 **设备对象**是"实例级"状态容器 —— 复用/换设备都会带出 `.custom` / `.locked` 残留（2026-09-20 实锤 A）：
    `exposureMode` / `whiteBalanceMode` 只会被**当前挂着的那台设备**改写；别的镜头仍留着旧档位，
    而 `removeInput` / `addInput`、甚至**复用同一个 device 对象**都**不重置**它。
    所以"换设备后按旧快照重放"之前**必须先归一新设备**（`normalizeToAutoLocked`），否则推 EV 会撞上
    残留的 `.custom` → 被回切 + WRN（批三 2 次实锤；日志特征是"只搬白平衡 + 推 EV"、**没有**"手动曝光已重放"）。
    **判据：跨设备搬运 = 先归一，再重放；永远不要假设新设备的档位是干净的。**
12. 🔴 **形态切换的转场边界按"用户视角"分类，不按实现分类**（2026-09-20 用户要求 ③）：
    用户口径 = **只有点焦段档位**该看到转场（≤1s）；切手动 / 开对焦盘 / 切模式 / App 自己回切
    全部要"人眼无感"。做法：`applyFocalTargetSilently`（**不置 `isLensSwitching`** ⇒ 不显示模糊）
    承担所有"非用户焦段"的换设备（**后台预切换** + **回切虚拟**）；`beginFocalSwitch` 只服务焦段点击。
    ⚠️ 连带坑：入口动作**不能挂在 `isLensSwitching` 边沿**（静默路径不置它 → 表现为"点了没反应"），
    必须挂在 `form` 边沿 + 1.2s 转场兜底。⚠️ **静默省的是"模糊"、不是"耗时"** ——
    换 input 固有 0.6~0.75s 停顿仍在（模糊的价值正是盖住它），所以静默只用在用户没在等切换的时刻。
13. 🔴 **对焦读数 0.00 是"最近端 / 未收敛"，不是可锁的"当前值"**（2026-09-20 问题 4）：
    换到 120mm 后新设备 `lensPosition` 冷帧读回 0 → 关「自动对焦」把它锁成手动档 →
    焦点死在最近端、画面全跑焦，且此后点按全走"仅测光"**无出路**（批三 40 次点按实锤）。
    判据：**推断出来的值要守卫，用户显式给的值不守卫** ——
    "关自动对焦"是**推断**"就锁在现在这里" → 读数必须 `finite && > 0.01`，否则拒绝 + toast；
    而圆盘**显式**拖到 0.00 是用户真实意图 → 照写。
14. 🔴 **`commitConfiguration()` 返回 ≠ 系统已完成工作**（2026-09-20 批五 · 真凶级）：
    切模式重配 outputs / 换设备都会让会话**重新协商 `activeFormat`**，而那次落地**发生在我们重放之后**，
    把刚写进去的 `.custom` / `.locked` 清成自动 —— 表现就是"手动模式切完模式回到自动"。
    **判据：凡是"改完会话配置 → 立刻按意图写设备参数"的地方，都要有"延迟复查 + 被清就补写"这一层**
    （`reverifyManualIntent`：150/300/500/800ms 四拍；补写前**先核对已发布的意图态**，
    用户中途点回自动就**不能**按回去 —— 否则变成"我点了自动它自己又跳回手动"）。
15. 🔴 **等异步任务用"回执"，不要用"盲等超时"**（2026-09-20 批五）：盲等分不清"慢"与"没做" ——
    入口排队"等 1.2s 就退转场"而冷探测要 4.2~5.0s → **必然退转场**（越修越糟）。改成结果回执
    （`SilentSwitchOutcome`：switched / alreadySatisfied / skipped）。⚠️ **"已经满足"必须单独一个回执**
    —— 否则调用方会在"不会再有边沿"的状态上死等（预切换抢先完成时 `form` 不再变化 → 排队动作永不执行 = "点了没反应"）。
16. 🔴 **工具坑：并行编辑同一个文件会丢写入**（2026-09-20 本轮连踩两次）：
    一条消息里对**同一个文件**发多个编辑，会出现"都报成功、但只有部分落盘"——
    被丢的那处留下旧代码（本轮丢了 `prewarmFocalTarget` 改名，差一点带着编译错误提交）。
    **做法：同一文件的多次编辑必须串行；改完用 `git diff --stat` + grep 关键符号逐个核对。**
