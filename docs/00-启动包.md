## 三、工程纪律（8 条 · 摘自 `docs/04`，完整版读那份）

1. **分层**：UI（View/VM）不碰设备；设备一切写操作只走 `CaptureDeviceConfigurator`
2. **唯一锁**：`beginConfiguration` / `lockForConfiguration` 只在 configurator ——
   别处出现 `setExposureModeCustom` / `ramp` / `setWhiteBalanceModeLocked` 都是错（自检会拦）
3. **事件驱动，不轮询**：硬件状态变化由会话**主动发布**（`@Published`），UI 只订阅；
   例外：每秒的调试快照 `refreshSnapshot()`（只写日志，不驱动 UI）
4. **单一真源**：预设数据（滤镜/风格/场景/焦段/格式/**刻度条**）以原型为真源，
   由 `tools/check_presets.js` 逐条比对；Swift 侧绝不抄第二份
5. **浮层互斥逐点接线**：新增浮层必须同时进 `collapseOverlays()` 与 `dismissTransientPopovers()`，
   且**展开者自己不能调后者**（会把刚展开的自己收掉）
6. **push 纪律**：先 `git fetch`；**合并用 `git merge FETCH_HEAD`，绝不强推**；
   `git add` 按路径明确列出（**禁 `-A`**）；走加速器 `-c http.proxy=http://127.0.0.1:7892`（不 --global）
7. **节奏**：先出方案 → 用户确认 → 再写代码；做完一步汇报产出与遗留，等确认再下一步
8. **每件交付都要有自检 + 变异测试**：新加的守卫必须"注入坏数据"验证真的会报错，
   并跑一次未变异的对照组（否则等于没加）

**双机协作分工**：WB（本端）改 Swift + 自检；**CB / Mac 侧**改 `prototype/index.html`

## 四、长期记忆里的关键坑（都是真踩过的）

1. 🔴 **Swift `catch` 不到 ObjC 异常** —— 只能在"入参是否合法"上防；`catch` 是幻觉。
   读硬件状态的 API 先问"它此刻处于有效状态吗"（`startRunning()` 是异步的）
2. 🔴 **`let` 带默认值的属性不进 memberwise init** —— 配置字段要用 `var`，
   否则传参报 "extra argument"（编译才暴露，代价一轮往返）
3. 🔴 **`AVCaptureDevice` 不暴露镜头绝对焦距** —— 别用 mm 相除；
   按**镜头角色**读设备（`virtualDeviceSwitchOverVideoZoomFactors` + 原生阶梯）
4. 🔴 **自检守卫的作用域**：断言"某函数里必须有什么"要用 **`methodBodyOf` 切方法体**，
   全文匹配会被**别处同类代码**满足（假绿）；**字符窗口**会被注释挤爆（假红）
5. 🔴 **两条检查脚本会"打架"** —— 断言语义跨两个文件时，只能放**两边都读**的脚本里
6. 🔴 **镜像/同步必须整目录**，且顺序固定：**① D: fetch+merge → ② D:→工作区 → ③ 改 →
   ④ 工作区→D: → ⑤ add/commit/push**。硬编码文件清单会**静默少同步**；顺序颠倒会覆盖别人的改动
7. 🔴 **几何账要写成可执行的检查**（读令牌 + 逐机型复算），文档只贴脚本打印的数字 ——
   手算表已两次漏项（`docs/11` 漏常驻条 / `docs/16` 漏顶栏块，各乐观 8.5pp）
8. **2pt 余量 = 危险信号**（`docs/11` 的 50.2% 就是 2pt 余量），宁可压高度换 6pt
9. **中文字宽可按 1.0em 推，拉丁/数字必须实测**（「120 mm」实测 40.0pt，估算窄 25%）
10. **SF Symbol 名写错 → 静默留白**（编译与自检都拦不住）；小图形用 `Path` 自画更稳
