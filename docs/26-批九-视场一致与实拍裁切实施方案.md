## 二、目标口径（验收定义）

- **⑥**：**窗内渲染的视场 == 成片视场**。两者同源于同一帧 `CVPixelBuffer`，窗内 = 整帧按遮幅比 fit
  （4:3 时 = 整帧），构造性成立，不再依赖预览层的黑盒裁切。背景层照旧满屏 fill（窗外暗化看氛围）。
- **实拍裁切**：遮幅 16:9 / 1:1 时，**照片按与窗内完全相同的 rect 居中裁切**后入库；4:3 = 整帧不裁。
  裁切 rect 只有一个来源（§三 的纯函数），渲染与拍照共用 ⇒ 不可能"窗里一套、成片一套"。
- **成片范围提示**（docs/24 §四建议）：窗 = 拍照范围本体 + 窗外暗化既有实现（遮幅黑边），不再另做一层。

## 三、架构与数据流

1. **流**：`AVCaptureVideoDataOutput`，`videoSettings` 一次设死 **420v**（12bpp，带宽 1/2.7 于 BGRA；
   与探测优先序同族；实测有条带再升 420f，Mac 观察）。专用串行队列投递，
   `alwaysDiscardsLateVideoFrames = true`。
2. **渲染**：帧 → `CIImage(cvPixelBuffer:)` → 缓存好的几何变换 → `RenderContext.context.render`
   进目标 drawable 纹理（输出 Display P3，沿用 RenderContext 约定）。**逐帧零分配**：变换矩阵 /
   cropRect 全部按"帧尺寸 + 遮幅档 + 布局"三元组缓存，变化才重算。
3. **几何纯函数（单一真源）**：`cropRect(videoSize:maskRatio:)` 与 fill/fit 变换各只有一份实现，
   渲染窗、实拍裁切、点按换算（刀 2）全部调它 ⇒ 配套几何账脚本（纪律 7：脚本复算，不手算）。
4. **帧尺寸自适应**：冷探测 / B4 `applyFormat` 改了 `activeFormat` ⇒ 缓冲尺寸变 ⇒ 渲染器按
   "帧尺寸失配"自动重算变换。**这是与批七的唯一接口，无其他耦合**。
5. **转向 / 镜像**：数据流连接上 `videoRotationAngle = 90`（**先查** `videoRotationAnglesSupportedValues`
   含 90 再写 —— 坑 #9 逐字对应）+ `isVideoMirrored = (前摄)`。写操作一律走 configurator（纪律 1/2）。
6. **门控（防掉帧项恶化）**：流**常驻**，不随模式拆装；离开相机页 / 退后台 / 会话打断时用
   `connection.isEnabled` 关停（连接属性写也归口 configurator）——不触发会话重配，不给 0.30s 抖动加码。
7. **限帧**：软件限 30fps（渲染回调里比较宿主时钟，不到间隔直接丢帧）——不碰任何帧率弃用 API；
   探针已证该输出 30fps 恒稳（v1 三相位 30.0/30.0/30.0）。

## 四、两刀切（风险从低到高排）

| 刀 | 内容 | 碰什么 | 碰不碰什么 |
|---|---|---|---|
| **刀 1** | 窗内自绘：遮幅开口处挂一块 Metal 窗视图（`isUserInteractionEnabled = false`），fit 渲染整帧 | 新增流 + 新窗视图 + 实拍裁切 | **预览层 / 点按手势 / 快门 / 资源账预期全不动** |
| **刀 2** | 背景换自绘：预览层退役，背景也走自绘 fill | 删 `AVCaptureVideoPreviewLayer`；`captureDevicePointConverted` 换成自有纯函数（fill 逆变换）+ roundtrip 脚本守卫 | 手势/快门挂点不动；**Mac 必须复验批六 ③ 全链** |

刀 1 落地 = "窗 == 成片"成立 = **P4 前置解除**；刀 2 是观感/一致性升级，允许在真机数据出来后单独拍板。

## 五、成本 / 功耗 / 延迟评估（预估口径，§八 有实测项）

- **拷贝代价**：420v = 12bpp；1440×1920 帧 ≈ 4.2MB/帧 ≈ **126MB/s** @30fps（CI 内部对 CVPixelBuffer
  上传有缓存，无逐帧分配）。两表面合计渲染 ~4-5MP/帧，A18 GPU 单帧 **3-6ms**（<5% 占用）；刀 1 只渲染
  窗（~1-2MP/帧），再省一半以上。
- **功耗对比（预估）**：预览层路径 = ISP 直出、GPU 空闲；自绘 = +GPU 常渲染 +~126MB/s 带宽。
  整 SoC 口径：**刀 1 +3~6%、全量 +5~12%**（大头仍是传感器+ISP+屏幕）；30fps 下热预期无感。
  → Mac 以 10min 标准会话实测（§八-5）。
- **延迟**：帧到达 → 排队(≤33ms) + CI 渲染(3-6ms) + drawable 呈现(≤16.7ms) ≈ **50-70ms 端到端**；
  预览层基线 ~30-45ms ⇒ **Δ ≈ +1 帧（20-30ms）**。拖影手感由 Mac 拍屏法判（§八-4）。
- **质量边界（诚实）**：420v 预览为 SDR，HDR 高光表现与预览层有差；自用取景可接受，记为已知偏离。

## 六、与 P4 渲染栈的复用（结论：已经共用，无需"打通"）

- `RenderContext` 就是 docs/24 §六 P4b 指定的那个 Metal `CIContext`（工作空间/输出空间逐字一致）。
- ⑥ 的窗渲染器 = **P4 实时预览的"零滤镜版"**：P4b 只需在 `CIImage` 与 `render` 之间插入滤镜链
  （LUT `CIColorCubeWithColorSpace`），渲染骨架、色彩口径、表面管理全部复用。
- `PHLivePhotoEditingContext` / 视频导出等 P5/P6 链路同吃这一个 context，互不新增实例（防内存暴涨，
  RenderContext 文件头已钉死该纪律）。

## 八、真机必验清单（Mac 判官，按刀标注）

1. **窗 == 成片**：拍一张，成片与窗区域叠对（截图 diff + 并排目检）—— 刀 1 核心判据。
2. **实拍裁切对账**：16:9 / 1:1 各拍一张，成片尺寸与方向符合遮幅比，内容 == 窗内。
3. **点按对焦全链**（批六 ③ 四拍口径）：刀 1 应零变化；**刀 2 后必须全量复验**（换算换了实现）。
4. **延迟**：拍屏法（对秒表/滚动画面摄录屏幕）对比预览层基线录屏 —— 刀 2 必做，刀 1 抽测。
5. **功耗/热**：10min 标准预览会话（thermal state + 电量 + ④ 周期账），刀 1 / 刀 2 各一轮。
6. **fps 稳定**：渲染计数日志 30fps 上下，掉帧率 <5%。
7. **冷启动复测**：新增 output 后 c 口径仍 ≤1.1s；**资源账预期数每模式 +1（流常驻）**，0「资源超出预期」。
8. **方向与镜像**：竖拍方向正确；前摄镜像正确（与原预览层行为一致）。
9. **打断 / 后台恢复**：窗画面恢复、无永久黑窗（对照探针"重挂救不回"——自绘路径必须自愈）。
10. **与 B4 咬合**（批七落地后）：切 4K/60，窗画面尺寸跟随、WYSIWYG 不破；`phys_footprint` 无逐帧增长。
