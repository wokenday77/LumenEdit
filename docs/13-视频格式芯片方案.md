## 零、一句话结论

芯片是**顶替**右上三图标（不是新增一颗）——视频 / Log 实况模式下，右上角三图标整组隐藏、
原位显示格式芯片；点它弹出**右上角下拉选择器**（分辨率 3 项 + 帧率 4 项）。
芯片**必须钉成 73pt 宽**（= `topBarSideWidth`），否则模式条的盒中心会跟着漂。

## 一、位置（含几何账）

```
┌ 顶栏主行 ────────────────────────────────────────────────┐
│ 电平表 73 │        模式条（居中）        │ 三图标 73      │  ← 照片 / 实况
│ 电平表 73 │        模式条（居中）        │ [4K · 30] 73   │  ← 视频 / Log 实况（芯片顶替）
└──────────────────────────────────────────────────────────┘
                                              ↓ 点芯片
                                    ┌──────────────────┐
                                    │ 分辨率  720p 1080p 4K │  ← 右上角下拉（196 宽）
                                    │ 帧率    24 30 60 120  │
                                    │ ──────────────────    │
                                    │ 剩余可录时长按码率估算… │
                                    └──────────────────┘
```

| 项 | 值 | 出处 |
|---|---|---|
| 可见条件 | `CaptureSessionMode.isRecordingBased`（= `.video` / `.logLive`） | 原型 `.mode-video/.mode-log` |
| 芯片最小宽 | **= `Theme.Size.topBarSideWidth`（73）** | 原型 `min-width:var(--tb-side-w)` + 注释 |
| 芯片自然宽 | `4K · 30` ≈ 60 → 被 73 撑到 73（胶囊稍宽）；`Log · 4K · 30` ≈ 91 > 73 | 原型注释（第九轮已确认接受） |
| 选择器定位 | 右上角：**顶栏下沿 + 6**，右边距 **14** | 原型 `right:14px; top:92px`（92 = 状态栏 30 + 顶栏 56 + 6） |

> ⚠️ **73pt 这条不是审美，是几何硬约束**：模式条"居中"靠的是左右两侧等宽（`topBarSideWidth`）。
> 芯片若用自然宽（60/91），模式条盒中心就会漂 12.6 / 9.1pt —— 后者原型已明确接受
> （`CONTEXT_HOT` 第九轮："Log 实况偏 −9.1，用户已确认接受"），前者必须靠 `min-width` 钉住。

## 六、连带改动

1. **副行存储胶囊在录制类模式常显**：`chip-storage` 在 `.mode-video/.mode-log` 下 `display:inline-flex`
   —— 即使用户把设置里的「存储空间提示」关了，视频模式下也必须显示（拍摄关键信息）。
   Swift 侧：`TopBarView` 里修存储胶囊的可见条件为 "`组存储提示开关` **或** `mode.isRecordingBased`"。
2. **录制类模式下胶囊文本换成时长估算**：原型 `≈ 85 min · 31 GB`。
   复用**已有**能力：`DeviceStorage.estimatedRecordingTimeText(megabitsPerSecond:)` +
   `DeviceStorage.availableBytes()`（交接单说的"估算能力已备好"，本件直接用，不新增）。
3. **码率表**（原型占位，真机读 `AVCaptureDevice` 推荐录制设置）：

   | res \ fps | 24 | 30 | 60 | 120 |
   |---|---|---|---|---|
   | 720p | 9 | 11 | 18 | 28 |
   | 1080p | 14 | 18 | 28 | 42 |
   | 4K | 38 | 48 | 50 | 96 |

   （单位 Mbps）→ Swift 侧放一个 `VideoFormatCatalog`（与 `Presets/` 里的目录同风格），
   **单一真源**：芯片文案、时长估算、B 组重设格式三处共用。

## 八、自检增强（`tools/check_swift.js` 第 10 组）

| # | 检查 | 为什么 |
|---|---|---|
| ① | 芯片**最小宽引用 `topBarSideWidth`**（不是写死数字） | 模式条居中依赖两侧等宽 —— 写死就断了联动 |
| ② | 芯片只在 `isRecordingBased` 模式渲染；三图标在同条件下隐藏 | 顶替关系错一半会出现"两个都显示"或"都不显示" |
| ③ | 选择器选项 **3 + 4 项**，且分辨率/帧率两组都在 | 版式回归 |
| ④ | 码率表 **12 个值全部 > 0**，且 res/fps 键与选项集合一致 | 缺键会静默落到默认码率（`|| 50`），时长显示错得很隐蔽 |
| ⑤ | 落盘 2 键（`lumen.camera.fmt.`） | 原型存 LS_SHOOT |
| ⑥ | 与功能面板互斥（两处 `isFunctionPanelExpanded = false` / `isFormatSelectorExpanded = false`） | 两层浮层叠加 |
| ⑦ | 存储胶囊常显条件含 `isRecordingBased` + 时长估算调用 | 拍摄关键信息不能被设置开关藏掉 |

## 九、风险与回退

| 改动 | 风险 | 回退 |
|---|---|---|
| 芯片顶替三图标 | 芯片比三图标"重"（73pt 实底 vs 三个小图标），顶栏右侧视觉重量变化 | 芯片宽/底色是两个令牌，改回自然宽即可（但会破坏模式条居中） |
| 选择器弹在右上角 | 与顶栏副行「剩余存储」胶囊位置接近（副行在顶栏内、选择器在其下方 6pt） | 定位是"顶栏下沿 + 6"的相对表达式，改偏移即可 |
| 默认 `4K · 30` | 若你想要 60（原型口径），改一个常量 | 见第五节 A/B |

## 十、Mac 截图 / 真机验收清单

1. 切到**视频**模式 → 右上三图标消失，原位出现 `4K · 30` 芯片；**模式条仍在屏幕正中**（不漂）
2. 切到 **Log 实况** → 芯片变 `Log · 4K · 30`（比 73 宽 → 模式条偏左约 9pt，原型已接受）
3. 点芯片 → 右上角下拉出现：分辨率 3 项 / 帧率 4 项，当前项 accent 底 + 深色字
4. 选 `1080p` / `30` → 芯片文案变 `1080p · 30`；**剩余可录时长跟着变**（时长应该明显变长）
5. 切回**照片**模式 → 芯片消失、三图标回来
6. 副行存储胶囊在视频模式下**常显**，且文本是 `≈ N min · X GB`；照片模式下回到 `X GB`
7. **互斥**：开着功能面板点芯片 → 面板收起；开着选择器点 ⠿ → 选择器收起
8. 点别处（取景器 / 快门 / 模式条）→ 选择器收起
9. 冷启动 → 记住上次选的 `res · fps`
10. 底注文案在（"重设采集格式属 B 组"），选完的 toast 也说明这一点（不做"点了没反应"）
