## 一、实锤 A · EV 杀手动"残留场景"（🔴）

**现象**（Mac 批三）：15:15:00.218 / 15:15:44.524 两次 WRN `推 EV 时设备处于手动曝光档 → 已回切自动档`，
且那两次日志只出现「只搬白平衡 + 推 EV」，**没有**「手动曝光已重放」。

**根因**：判据只看**旧设备快照**。`exposureMode` / `whiteBalanceMode` 是**设备实例级**状态 ——
"退出手动档"只改**当前挂的那台设备**，别的镜头仍留着 `.custom` / `.locked`；
`removeInput` / `addInput`（甚至复用同一个 device 对象）**都不重置**。
于是新设备自带上一轮残留 → 我们按"旧设备是自动档"去推 EV → `applyExposureBias` 见 `.custom` 就回切自动 + WRN。

**改法**（两条都做，互为表里）：
1. 新增 `CaptureSessionController.normalizeToAutoLocked(on:)`：换设备/切模式时**先把新设备归一到自动档**
   （曝光 + 白平衡都清），再按旧设备快照重放 —— 目标态**唯一确定**，不再依赖新设备的陈旧档位；
2. `reapplyManualStateLocked` 推 EV 之前**再判一次**新设备是否仍在 `.custom`（防线：将来谁把 ① 删了，
   日志里会立刻出现 `EV 重放前新设备仍是手动曝光档 → 先归一`，而不是又退化成一次静默的"手动档被杀 + WRN"）。

**Mac 复验口径**：
- 换设备 / 切焦段后**不再出现**那条 WRN；
- 必有一条 **「换设备后新设备档位复查：曝光=自动 / 白平衡=… / 对焦=自动（显式降级） / EV=…」**；
- 若真出现残留，会先有一条 `新设备带上一轮手动档残留（曝光=手动 …）→ 已归一到自动档，再按快照重放`。

**自检**：⑲ n 段 `normOK1`（有归一调用）+ `normBeforeEv`（**归一必须在 `applyExposureBias(` 之前**）+ `normImplOK`（两个档位都归一，不能只清一半）。

## 二、实锤 B · 跟手倍率方向写反（🟠）

`let raw = dragStartOffset + gesture.translation.width / Self.dragGain`（dragGain = 1.5）
= 指尖要拖 1.5 个档距才走一档 → **比改前更钝**。批三注释里"1 秒连推 5 档太灵敏"是误读
（那 5 次是**同一个值**重复推，证据指向"不灵敏"）。

**改法**：`* Self.dragGain`（指尖 1pt → 盘面 1.5pt；走一档只需 1/1.5 个档距的指尖位移），上限仍 1.2~2。

**自检**：`gainOK` = 倍率 ∈ [1.2, 2] **且**是 `*` **且**不是 `/`（加了反向判据）。

## 三、用户问题 1 · 刻度条还是不对（🔴）

四条症状（刻度值对不准 / 卡点不准确 / 卡点回弹 / 对应数值不对 + **外形没有变化**）拆成两件事修：

### 3.1 外形：改用原型 CSS 里**本来就有的四档层级**

原型 `.sp-tick` 家族一直是**四档**，但它的 JS `renderStrip` 只给 `major` / `preset` 打了类 ——
`mid` 那一层**定义了却没人用**。Swift 侧照 JS 抄，于是"主档之间的细刻度"只能自己发明：
**1px 宽 / 20% 白 / 半高发丝线** —— 用户实测"外形没有变化"（太淡 + 档距偏疏）。

| 档 | 原型 | 高 | 颜色 | 本轮归属 |
|---|---|---|---|---|
| `minor` | `.sp-tick` | 10 | 白 34% | ISO 的 1/3 档 |
| `mid` | `.sp-tick.mid` | **15** | 白 **48%** | ISO 整档（每 3 步）、WB 的 100K 档、**快门半档细线** |
| `major` | `.sp-tick.major` | 22 | 白 82% | 带数字的档（原型 `labelAt`） |
| `preset` | `.sp-tick.preset` | 22 | 琥珀 85% | WB 的 5 个预设档 |

- 分级规则落在数据层 `ParameterStripCatalog.tickTier(for:index:step:)` + `hasHalfStepTicks(_:)`（可被自检断言）；
- **快门**是唯一加"档间细线"的条：它 15 档全是主档、档距 56pt，最疏 → 补 14 条半档位置的 `mid` 线，
  密度翻倍、层级自然出现。⚠️ 这些线**不参与吸附**（纯视觉细分，与真实档位的 82% 亮线高度/亮度明确区分）；
- **ISO 不加合成线**：它那 25 条本身就是可吸附的 1/3 档真实档位，再塞视觉线会与档位混淆 —— 层级靠 mid/major 表达；
- 顺带修正一处**偏离原型**：`preset` 档（如 5200K，不是 500 的整数倍）原先只改色**不改高**（10pt），
  原型是 22pt —— 已改齐。

### 3.2 回弹：松手后草稿**不再立刻清**，等硬件回读"同档"

松手那一刻 VM 立刻清草稿 → 显示交回**还没更新**的硬件回读（写硬件是异步的：
sessionQueue → 设备锁 → publish → 订阅）→ 刻度条按**松手前的旧值**算档位 →
**条子先弹回旧档、几十毫秒后再跳回来**（用户实测"卡点回弹"；叠加"松手吸附值 ≠ 回读值"
就是"对应数值不对"）。

**改法**（与 EV / 对焦同一条"回写闸门"纪律）：
- 松手时**保留草稿**，改由订阅 `$manualExposure` / `$manualWhiteBalance` 的 `settleStripDrafts` 清账；
- 判据**与渲染口径同源**：比"回读值吸附到的**档位**"是否 == "草稿吸附到的档位"
  （用 `ParameterStripCatalog.nearestStep`，而不是两个 Double 逐位比 —— 设备对 ISO / 时长有量化，
  逐位比会永远 settle 不了）；
- 0.8s **超时兜底**（`scheduleStripDraftTimeout`）：写入被 clamp / 被拒时强制交回硬件真值，草稿不会压死显示。

**Mac 复验口径**：拖动后松手，条子**不回跳**；若出现 `刻度条草稿 0.8s 未与硬件回读对齐` 说明写值被 clamp 过（正常兜底）。

## 四、用户问题 2 · 切焦段和模式，参数还是回自动（🔴）

切焦段这一半 = 实锤 A（已修，见第一节）。切模式这一半原来用"比对 commit 前后、只有被系统清掉才重放"——
**判据依赖"系统到底改没改"**，而批三那 3 次切模式时手动档未激活，口径根本没被验到。

**改法**：**一律按快照重放**（幂等：写同样的值）。顺序定死为
**① 归一 → ② 曝光重放 → ③ 白平衡重放 → ④ EV 重放（仅自动曝光档）→ ⑤ 复查日志**。
新增一条 **「切模式后档位复查（模式名）：曝光=自动/手动 / 白平衡=… / 对焦意图=… / EV=…」**，
让复验直接读实际档位、不靠推断。

**自检**：`modeKeepOK` 要求"有归一 + 两个 `if let prev` 无条件重放 + EV 仅自动档 + 代码里**不再出现** `afterExposure`"。

## 五、用户问题 3 · 转场该有/不该有的边界（🔴）

**用户口径**：只有**点焦段档位**该有转场且 ≤1s；切自动/手动、点对焦按钮、切模式 → **人眼无感**。
（批三现状：点对焦会触发转场、其他入口也走同一转场，时长 0.10+0.6~0.75+0.15 ≈ 0.85~1.0s。）

**改法**：把换设备从"用户按下按钮那一刻"挪到**更早或更晚的非焦点时刻** ——
新增 `applyFocalTargetSilently(_:)`：与真转场**共用同一个执行体** `performFocalSwitch(_:throughTransition:)`，
唯一差别是**绝不置 `isLensSwitching`**（那个位是"UI 显示模糊浮层"的信号）⇒ 纯后台、无浮层。

| 入口 | 现在走哪条 | 用户看到 |
|---|---|---|
| 点焦段档位（跨镜头） | `beginFocalSwitch` → 转场（`commitFocalSwitch` 由淡入完成回调触发） | 模糊 ≤1s |
| 打开刻度条 / 按「对焦」 | **静默预切换**（提前把物理设备挂好） | 无转场（可能有换 input 的一瞬停顿） |
| 点手动开关 / 开对焦盘（设备已挂好） | 直接写参数 | 无转场 |
| 全手动档退出 2s 后回切虚拟 | **静默回切** | 无转场 |
| 切模式 | 会话内重配 outputs，本来就没有转场 | 无转场 |

**连带修的两处**：
1. 入口动作**改挂 `form` 边沿**（原先挂 `isLensSwitching`）—— 静默路径不置那个位，
   挂错会让"已经预切换好的用户"点手动开关**什么都不发生**（点了没反应）；
2. **1.2s 转场兜底**（`queueActionRequiringPhysical`）：预切换被跳过时（录制中 / 会话未就绪 / 真转场插队）
   自动退回 `beginFocalSwitch`，入口永不死亡；
3. 回切防抖加**参数界面闸门**（`isParamSurfaceOpen`）：刻度条 / 对焦盘开着时**暂不回切**，
   否则预切换刚挂好的设备会被 2s 防抖换回去（白做一次换设备 + 多一次转场）。

**⚠️ 要如实告诉用户/复验方的代价**：静默路径省掉的是**模糊**，不是**耗时** ——
换 input 本身 0.6~0.75s 仍在（预览可能有一瞬停顿）。模糊转场的价值正是盖住它，
所以静默只用在"用户正在做别的事"的时刻（开面板 / 收面板后 2s）。

## 六、用户问题 4① · 120mm 下无法触碰对焦（🔴）—— 已修一半

**根因（Mac 已定位）**：15:15:02 在对焦圆盘里关掉「自动对焦」→
`自动对焦已关 → 手动（当前值 0.00 锁定）`→ 焦点锁死在**最近端**、画面全跑焦；
此后所有点按都走"仅测光"（拍板 ③ 不改 `focusMode`）→ 整场 40 次点按**没有任何出路**。

**已修：① 锁定值有效性守卫**（`focusAutoToggled`）：
- 改用 **session 真值** `currentLensPosition` 判定（不读 VM 显示值 —— 回写闸门可能让它停在旧读数上）；
- 有效 = `finite && > 0.01`（`isValidFocusLockReading`）：**0.00 端点 = "最近端 / 未收敛"**，锁上去必然跑焦；
  上界（1.0 = 无穷远）**不排**，锁无穷远是合法选择；
- 无效 → **不写手动档**（保持自动）+ toast「对焦读数尚未就绪（0.00）→ 保持自动对焦；先点按取景器对焦，或直接拖动圆盘手动调」+ warn 留痕；
- **不守卫圆盘拖动**：用户**显式**拖到 0.00 是真实意图，照写。判据 = **推断出来的值要守卫，用户显式给的值不守卫**。

## 七、用户问题 4② · 手动锁定下"点按取景器"的语义 —— **待用户拍板**

现状（拍板 ③，2026-09-19）：手动对焦锁定期间，点按取景器**只测光、不动焦**，
且**没有任何提示** → 用户以为"点按对焦坏了"（批三 40 次点按实锤）。三个候选：

### 方案 A（推荐）· 点按 = 「对焦 + 测光」，即**退出手动对焦档**
- 语义：与 iPhone 原生相机 / 飓风相机一致 —— 点按取景器就是"重新对焦"；手动锁定被点按解除。
- 实现：`focusTapped` 改走 `session.focus(atDevicePoint:)`，并在同一入口把对焦意图置回自动
  （`setAutoFocusMode()` → `manualFocus = nil`；自检⑱守的"意图入口"仍是显式写入点，不破纪律）。
- 好处：**永远有出路**（点一下就回来）；与主流相机一致，不用解释。
- 代价：手动锁定可能被一次误触解除。可加缓解：**对焦盘开着时**点取景器不解除（盘上是主操作场）。

### 方案 B · 保持「仅测光」，但给"明显提示 + 一键恢复自动"
- 语义：尊重"锁了就是不想动"（拍板 ③ 的原意），点按仍不动焦。
- 实现：手动档下点按 → ① 焦点框照常显示 + ② **焦点框旁挂一个"手动对焦已锁定"小角标**
  （点击 = 一键恢复自动）；③ toast 说明「手动对焦已锁定 · 点角标或对焦盘的「自动对焦」开关恢复」。
- 好处：零误触；出路**显式可达**。
- 代价：多一个 UI 元素（要核净可见账与遮挡）；点按仍不恢复对焦（多一次点击）。
- 提示噪音：手动档下点按会频繁 toast → 需要节流（建议同一条 toast 3s 内只报一次）。

### 方案 C（折中）· 点按动焦，但**要求二次确认**
- 语义：手动档下点按 → 焦点框显示 + toast「点按第二下 = 解除手动对焦并重新对焦」，
  3s 内再点同一区域才真正解除。
- 好处：不至于误触解除，也不至于"点了没反应"。
- 代价：交互多一步、实现最复杂（要记"上一次点在哪 + 时间窗"），且新用户不易发现。

**拍板请求**：请选 A / B / C（或在三者上改）。选定后我按老流程出改动 + 自检 + 变异测试再 push；
在此之前**不动点按语义**（本轮只做了第六节的 ① 守卫）。
