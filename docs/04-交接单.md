## 一、这是什么

自用 iOS 修图 App，对标醒图，功能范围可控。目标：照片 / Live Photo / 视频 三种媒体的**拍摄 → 编辑 → 导出**。

- **技术栈**：Swift + SwiftUI（相机预览与相机按钮用 `UIViewRepresentable` 包 UIKit）+ AVFoundation + Core Image + Photos
- **零第三方依赖**（App 运行时层面，一个都没引）
- **目标设备**：iPhone 16 系列及以上，最低 iOS 18.0，仅竖屏，仅 iPhone
- **最终形态**：7 个阶段，见 `docs/01-项目结构与第一阶段方案.md`

## 三、怎么跑起来（在 Mac 上）

```bash
# 1) 装 Xcode 16.0+（必须有 iOS 18 SDK）与 XcodeGen
brew install xcodegen

# 2) 取代码并生成工程（.xcodeproj 不入库，每次拉完代码都要生成）
cd <项目目录> && xcodegen generate

# 3) 打开
open LumenEdit.xcodeproj
```

Xcode 内：

1. TARGETS → LumenEdit → **Signing & Capabilities** → Team 选自己的 Apple ID
2. **Bundle Identifier 改成全局唯一的**（别用默认值，免费签名要求唯一）
3. iPhone 侧：信任电脑 → **设置 → 隐私与安全性 → 开发者模式**打开（**需重启手机**）
4. 顶部选中 iPhone → **⌘R**

> **必须真机。** 模拟器没有摄像头，相机会话会直接进"找不到后置摄像头"的失败态。
> **免费 Apple ID 签名 7 天过期**，到期重新 ⌘R 装一次。

完整版（含验收清单）见 `README.md`。

## 六、不能违反的纪律（8 条）

前 5 条来自 iOS 相机本身，后 3 条来自本项目的色彩/布局决策。**违反任何一条都会出 bug，而且多数是静默出错**。

1. **会话配置顺序不可调整**：
   `beginConfiguration` → `sessionPreset = .inputPriority` → `addInput` → 按模式 `addOutput` → `commitConfiguration` → **之后**才写 `activeFormat` / 帧率。
   默认 preset `.high` 会**静默覆盖**你的手动格式——这条顺序错了，表现只是"设了 30fps 实际还是 60"。
2. **`CaptureDeviceConfigurator` 是全工程唯一允许 `lockForConfiguration()` 的地方**，所有硬件参数写回前必须 clamp。越界是**抛异常**，不是被忽略。
3. **Live Photo 必须成对提交**：**同一个** `PHAssetCreationRequest` 内 `add .photo` + `add .pairedVideo`。两个 delegate 回调**顺序不保证**，所以按自生成的 `uniqueID` 配对，齐了才提交。绝不能"先存照片后补视频"。
4. **拍照保存走 `fileDataRepresentation()` 原始字节直存**，不做二次编码；显式关掉 `isAutoDeferredPhotoDeliveryEnabled`（开着会拿到代理图，"存出来的照片比预览糊"）。
5. **两个"唯一入口"不能绕开**：相册入库只走 `PhotoLibraryWriter`（它负责成对提交与错误映射）；硬件参数只走 `CaptureDeviceConfigurator`。
6. **LUT 三条纪律**：`CIColorCubeWithColorSpace` 且色彩空间**固定 sRGB**（漏了会色偏）；尺寸 32³；采样点在**线性空间**等距。
7. **渲染顺序定死**：线性化 → LUT → 高光阴影 → 柔光 → **降噪 → 锐化/结构** → 颗粒 → 暗角。降噪必须早于锐化；颗粒暗角必须最后。
8. **`landscape_teal_orange` 与 `mood_hongkong_warm_green` 互斥不可叠加**（阴影方向相反：一个冷青、一个暖绿，叠起来出脏色）。

另外两条产品级约束：

- **UI 不做"点了没反应"**：未实现的功能必须置灰并说明原因（`CaptureSessionMode.isImplemented` / `unavailableReason`）。点了没反应最容易被误判成"相机坏了"。
- **取景器铺满全屏，控件全是浮层，只遮挡不挤压**。互斥规则：同一时刻只允许一个扩展浮层展开，且任一展开时参数排自动收起 → 净可见取景面积永不低于 50%。

## 八、出问题怎么恢复

这个项目**没有不可逆操作**，恢复成本很低：

| 情况 | 恢复方式 |
|---|---|
| 工程打不开 / 工程文件乱了 | `.xcodeproj` 是生成物，删掉重跑 `xcodegen generate` 即可 |
| 某批代码引入问题 | 各批次的文件边界清楚，可按文件回退：**P1a** = 全部其余源码；**P1b-1** = 新增 `Camera/Output/LivePhoto*.swift` 两个文件 + 5 处接线改动（`CaptureSessionMode` / `CaptureSessionController` / `PhotoCaptureService` / `CameraViewModel` / `CameraView`） |
| 原型改坏了 | `prototype/index.html` 是单文件，随便试；`tools/check_prototype.js` 能立刻告出结构性错误 |
| 相册被测试照片塞满 | **手动删**。这是唯一需要人工收拾的东西 |
