## 四、工程纪律（8 条，来自 docs/04，违反出静默 bug）

1. **会话配置顺序不可调整**：`beginConfiguration` → `sessionPreset=.inputPriority` → `addInput` → 按模式 `addOutput` → `commitConfiguration` → **之后**才写 `activeFormat`/帧率。默认 `.high` 静默覆盖手动格式。
2. **`CaptureDeviceConfigurator` 是全工程唯一允许 `lockForConfiguration()` 的地方**，硬件参数写回前必须 clamp（越界抛异常，非忽略）。
3. **Live Photo 必须成对提交**：同一 `PHAssetCreationRequest` 内 `add .photo` + `add .pairedVideo`；两回调顺序不保证 → 按 `uniqueID` 配对，齐了才提交。
4. **拍照保存走 `fileDataRepresentation()` 原始字节直存**，不二次编码；显式关 `isAutoDeferredPhotoDeliveryEnabled`。
5. **唯一入口不能绕**：相册入库只走 `PhotoLibraryWriter`；硬件参数只走 `CaptureDeviceConfigurator`。
6. **LUT 三纪律**：`CIColorCubeWithColorSpace` 且色彩空间**固定 sRGB**；尺寸 32³；采样点线性空间等距。
7. **渲染顺序定死**：线性化 → LUT → 高光阴影 → 柔光 → **降噪 → 锐化/结构** → 颗粒 → 暗角。
8. **`landscape_teal_orange` 与 `mood_hongkong_warm_green` 互斥不可叠加**（阴影方向相反）。

产品级约束：
- **UI 不做"点了没反应"**：未实现功能置灰 + 说明（`CaptureSessionMode.isImplemented` / `unavailableReason`）。
- **取景器铺满全屏，控件全是浮层只遮挡不挤压**；同一时刻只允许一个扩展浮层展开 → 净可见永不 < 50%。

## 六、push 落盘纪律（必看，2026-09 踩过两次坑）

- ⚠️ **直连 GitHub 永不通**（本机被阻断），别在直连上浪费时间。
- ⚠️ 沙箱 env 里的代理（`http(s)_proxy`）会坏，报 `CONNECT tunnel failed, response 502`；
  **走用户的加速器**：`-c http.proxy=http://127.0.0.1:7892 -c https.proxy=http://127.0.0.1:7892`
  （**单次 `-c`，不要 `--global`**，端口动态）。
- ⚠️ **推送前先 `git fetch`**（曾因直接 push 被拒）；合并用 `git merge FETCH_HEAD`。
- ⚠️ **禁止 `git add -A`**；按路径明确 add 自己改的文件。
- 自检过了再 push：`node tools/check_swift.js LumenEdit`。

**推荐 push 命令**（失败自动重试 3 次）：

```bash
cd "D:/AI 工作存储/iPhone相机"
git fetch origin
node tools/check_swift.js LumenEdit
git add <你改的文件路径...>
git commit -q -F - <<'EOF'
<提交信息>
EOF
GitProxy="http://127.0.0.1:7892"
for i in 1 2 3; do
  git -c http.proxy=$GitProxy -c https.proxy=$GitProxy push origin main 2>&1 && { echo "PUSH_OK"; break; }
done
```
