## 四、工程纪律（8 条，来自 `docs/04` 第六节，违反出静默 bug）

1. **会话配置顺序不可调整**：`beginConfiguration` → `sessionPreset=.inputPriority` → `addInput` →
   按模式 `addOutput` → `commitConfiguration` → **之后**才写 `activeFormat`/帧率。
   默认 `.high` 会静默覆盖手动格式。
2. **`CaptureDeviceConfigurator` 是全工程唯一允许 `lockForConfiguration()` 的地方**，
   硬件参数写回前必须 clamp（越界是**抛异常**，不是被忽略）。
   > 推论（B1 用到）：**`device.ramp(...)` 也必须在锁内**，所以它只允许出现在这个文件里 —— 自检第 11 组会拦。
3. **Live Photo 必须成对提交**：同一 `PHAssetCreationRequest` 内 `add .photo` + `add .pairedVideo`；
   两回调顺序不保证 → 按 `uniqueID` 配对，齐了才提交。
4. **拍照保存走 `fileDataRepresentation()` 原始字节直存**，不二次编码；显式关 `isAutoDeferredPhotoDeliveryEnabled`。
5. **唯一入口不能绕**：相册入库只走 `PhotoLibraryWriter`；硬件参数只走 `CaptureDeviceConfigurator`。
6. **LUT 三纪律**：`CIColorCubeWithColorSpace` 且色彩空间**固定 sRGB**；尺寸 32³；采样点线性空间等距。
7. **渲染顺序定死**：线性化 → LUT → 高光阴影 → 柔光 → **降噪 → 锐化/结构** → 颗粒 → 暗角。
8. **`landscape_teal_orange` 与 `mood_hongkong_warm_green` 互斥不可叠加**（阴影方向相反）。

**产品级约束**：
- **UI 不做"点了没反应"**：未实现功能置灰 + 说明（`isImplemented` / `unavailableReason`；
  B1 的不可用焦段档位就是"**灰但仍可点**，点了 toast 说原因"）
- **取景器铺满全屏，控件全是浮层只遮挡不挤压**；同一时刻只允许一个扩展浮层展开 → 净可见永不低于 50%

## 五、踩过的坑（长期记忆精选，都是真金白银换来的）

1. **提交消息一律用 `git commit -F -` heredoc** —— 用 `-m "长消息"` 时消息里的英文引号会被 shell
   提前闭合 → **commit 失败，而 `&&` 后面的 push 照旧推上一笔**（看起来像成功）。
2. **新增/改 struct 成员前先 `grep -n "成员名" 该文件`** —— 两次同类事故：
   `focal` 被"新增式编辑"误删（编译失败）、`storageText` 重复声明（编译失败，Mac 代为修复）。
3. **SF Symbol 名写错会静默留白**（编译器和自检都拦不住）：`aperture` 不存在，
   正确的是 `camera.aperture`。新增符号必须列进 Mac 验收清单让真机肉眼确认。
4. **硬件值回写 UI 必须有"编辑态闸门"**（EV 回写环，`docs/14`）：`@Published` 回写 + 四段异步
   （sessionQueue → 设备锁 → `main.async` → RunLoop）→ 回写的是"几拍之前"的值。
   **判别特征：调某个"比值/增益"参数让问题更糟 → 多半是环路，不是阈值问题。**
5. **全局手势要挂整页容器**（`docs/11`）：挂在"下层兄弟视图"上，上层浮层一出现就吃掉那块区域的触摸
   → "第一次能呼出、第二次没反应"。另需**方向锁**（一次拖动只定一次主轴）+ 横滑控件的**编辑态闸门**。
6. **缓释机制的量级必须与"被缓解事件"同量级**：55ms 触觉节流 vs "每档 288ms 跨一档" = 形同虚设
   → 机制在但量太小等于没做（已加"量级守卫"到自检）。
7. **改「有预留/占位机制的控件」文本，必须同步改预留量级**：存储胶囊按"最宽文本"预留宽度，
   文本从 `31 GB` 变 `≈ 85m · 31 GB` 却不同步预留 → 复发"启动后跳宽"（还害得几何量错）。
8. **本地不能编译 → 静态检查是唯一防线**，且**新加的检查必须"注入坏数据"验证真的会报错**
   （否则等于没加）。自检现有：`check_swift.js` 10 组 + [2b] + [11]；`check_presets.js` 5 组。
9. **原型改版会让 Swift 侧"落后两轮"**：遇到"放不下/对不上"先回头核对原型**现在的形态**
   （焦段条曾被原型判为"浮层是回归"、改回底栈普通一行）。
10. **Mac 复验结论必须落盘才算数**：用户转述过"4 笔全过"而 git 里当时查不到 → **只认落盘证据**。
11. **几何账要点**：容器自身的 `spacing`/`padding` 也在账里；改了几何前提，**同一批算式必须重算**；
    **中文字宽可按 1.0em 推，拉丁/数字串必须实测**（「120 mm」10.5pt 实测 40.0pt，粗估会窄 25%）。

## 七、push 落盘纪律（必看）

- ⚠️ **直连 GitHub 永不通**（本机被阻断），别在直连上浪费时间
- ⚠️ 沙箱 env 里的代理会坏（报 `CONNECT tunnel failed, response 502`）；
  **走用户的加速器**：`-c http.proxy=http://127.0.0.1:7892 -c https.proxy=http://127.0.0.1:7892`
  （**单次 `-c`，不要 `--global`**，端口是动态的）
- ⚠️ **推送前先 `git fetch`**；合并用 `git merge FETCH_HEAD`（remote ref 可能不落 `refs/remotes`，正常）
- ⚠️ **禁止 `git add -A`**；按路径明确 add
- ⚠️ **长提交消息用 heredoc**（见坑 1）

```bash
cd "D:/AI 工作存储/iPhone相机"
git -c http.proxy=http://127.0.0.1:7892 -c https.proxy=http://127.0.0.1:7892 fetch origin
node tools/check_swift.js LumenEdit            # 必须全过
node tools/check_presets.js .                  # 动了 Presets/ 才需要
git add <按路径列出的文件...>
git commit -q -F - <<'EOF'
<提交信息>
EOF
GitProxy="http://127.0.0.1:7892"
for i in 1 2 3; do
  git -c http.proxy=$GitProxy -c https.proxy=$GitProxy push origin main 2>&1 && { echo "PUSH_OK"; break; }
done
```
