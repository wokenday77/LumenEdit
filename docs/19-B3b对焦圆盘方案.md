## 一、与 EV 圆盘的共用关系（为什么是重构而不是复制）

Mac 三改后的 `ExposureDialView.swift` 已经是"正确答案的形状"：相对位移拖拽、点击锚定不改值、
字号乘 scale、半透明盘底、两个 `.position` 前置的真机坑注释。复制一份 `FocusDialView`
等于把这份正确答案**抄一遍**——三条约定将来任何一条再调（比如盘底透明度再改），
就要人肉同步两处。Mac 的注释原话："届时应抽共享盘底，不要抄第二份"。

**重构形态**：

```
Camera/UI/DialView.swift          ← 新（由 ExposureDialView.swift 泛化重构而来）
  ├─ DialGeometry                 ← 纯几何（mirror / pointerDeg 参数化；半径体系不变）
  ├─ DialConfig                   ← 两盘差异全部收进这一个值（见第二节规格表）
  └─ DialView                     ← 盘底 / 刻度环 / 数字 / 指针 / 盘心 / 数值框 / 拖拽 / 开关行槽位
Camera/UI/FocusDialEntry.swift?   ← 不需要独立文件：CameraView 直接 DialView(config: .focus, …)
ExposureDialView.swift            ← 删除（内容并入 DialView；CameraView 的 EV 调用点改 config: .ev）
```

- **自动继承的机制**：盘底透明度、字号 ×scale、`dragAnchor` 相对位移模型、两个
  `.position` 前置坑 —— 全部只存在于 `DialView` 一处；两盘 config 不同而已。
- **回归风险与兜底**：重构动的是刚复验通过的组件 —— 兜底三层：
  ① 自检⑰的断言对象同步改为 `DialView.swift`（断言语义不变）；
  ② 变异测试脚本 `mutation-test-b3a.py` 锚点同步（并补对焦侧突变）；
  ③ Mac 复验 EV 盘回归（4 项快速口径：拖动顺滑顺走 / 点击不改值 / 字号 / 归零）。
- ⚠️ `ExposureDialView.swift` 文件名消失 → **Mac build 前需 `xcodegen generate`**（增删文件）。

## 二、两盘差异规格表（全部对齐原型，DialConfig 逐项来源）

| 维度 | EV 盘（`config: .ev`，现状不变） | 对焦盘（`config: .focus`，本件新增） | 原型依据 |
|---|---|---|---|
| mirror | `true`（露左半、右半出屏） | `false`（露右半、**左半出屏**） | `DIALS.focus.mirror:false`；圆心第 2 格 |
| 圆心 X | `md + xs + 5.5×格宽`（iconEV 第 6 格） | `md + xs + 1.5×格宽`（iconFocus 第 2 格，393 屏 ≈96.8，左裁 ≈26.2pt） | `--fd-center-x:83.1` = pad+1.5×格宽 |
| 指针角 | 270°（9 点，数值框盘左） | **90°（3 点，数值框盘右）** | `fdPointerDeg` |
| 值域 / 步进 | ±3 / 0.1 / 61 档 | **0 ~ 1** / 0.01（显示两位）/ 51 档 | `DIALS.focus`: count 51, min 0, max 1 |
| 档位分级 | 主 7（每 1EV）/ 中 6 / 副 | **主 11（每 0.1）/ 中 20 / 副 20**（`i%5==0` 主、`±1` 中） | `tickKind` |
| 数字文案 | `+1.5` / `0` / `−1.5` | `0.0 … 1.0`（一位小数，`toFixed(1)`） | `numText` |
| 数值框 | 盘左、**点击归零**（`+1.5 EV`） | **盘右、不可点**（`0.56`；≥0.995 显示 **∞**） | `.fd-val` 无 click 绑定；`fmt: val>=0.995?'∞'` |
| 盘下开关行 | 无 | **「自动对焦」开关行**（sw 29pt + label，盘下 gap 12） | `.fd-wrap` 第二个 flex 项 / `.fd-auto` |
| hub | ⊖ + 「曝光补偿」 | **◎（圆点 + 虚线圆 + 四向短线）+ 「对焦」**——自画 Path，不用 SF Symbol | `.fd-hub` svg |
| toast | 「拖动圆盘调 ±3 EV，点数值归零」 | 「手动对焦：拖动圆盘调焦（0.0 近 → ∞ 远）」 | 原型 toast 文案 |
| 几何复算 | 已在自检⑰ | 开关行**底沿距屏底 ≥ 0**：`centerY + 123 + gap12 + 29 ≤ 容器高`（读令牌复算，844/375 都验） | `--fd-gap:12` / `--fd-auto-h:29` |

**开关行语义（对焦盘专属）**：
- **开（自动对焦）**：调 `configurator.setAutoFocus()`（已存在，连续自动优先）；UI 锁定手动拖动
  （原型 `focusAuto → focusFromPoint return` 同款）；**不需要**原型的模拟动画（900ms 随机过渡
  是"原型没有真硬件"的代偿）——真机上 `lensPosition` 会被系统实时更新，**回读链驱动的读数
  自己会走**，比模拟更有质感。
- **关（手动）**：值停在当前处，恢复拖动。
- 开关状态**从硬件真值回读**：`focusMode == .locked` = 手动；`.continuousAutoFocus / .autoFocus` = 自动。
  不本地记账（与曝光/白平衡回读同纪律）。

## 三、数据链与编辑态闸门（本件补齐对焦的"回读三件套"）

曝光/白平衡已有"configurator 读 → session 发布 → VM 派生"三件套 + `docs/14` 闸门；
**对焦此前一条都没有**。本件补齐（全部照抄既有结构，不发明新形状）：

1. `CaptureDeviceConfigurator.manualFocus(of:) -> Float?`：`focusMode == .locked ? lensPosition : nil`
   （与 `manualExposure(of:)` 同构；顺带在**点按对焦**后由既有 `publishManualState` 自然覆盖）。
2. `CaptureSessionController`：`@Published private(set) var manualFocus: Float?`，在
   `publishManualState` 里随其它真值一起发布；**拍板 ③ 的执行点也在这里的调用方**
   （手动锁定期间点按对焦 → `focusTapped` 分流：只 `setExposurePoint` 不动焦，VM 层判
   `manualFocus != nil`）。
3. VM：`isFocusManual` 派生 + `focusEditingChanged(_:)`（`lastPushedLensPosition` +
   拖动期不回写 + 只接受最后推送值 —— `docs/14` 同构）+ `focusDialValueChanged`。
4. 自动对焦开关状态 = `manualFocus == nil`（派生，同 `isISOShutterAuto` 的做法）。

⚠️ **点按对焦的分流**（拍板 ③ 落地点）：现有 `setFocusAndExposurePoint` 会把曝光和**对焦**
一起打回自动 —— 手动锁定期间 VM 层改调"只测光"路径（`setFocusAndExposurePoint` 拆分出
仅曝光变体，或在 configurator 加参数），** hardware 层不动焦**。这是 2.4 表"显式降级"之外的
另一条点按语义，实施时一并落。

## 四、方向语义：**建议保持现状**（用户问询的意见）

**结论：保持"顺时针滑 = 值减小"，不改镜像。** 三条依据：

1. **数学上它被"顺滑顺走"锁死**：刚复验通过的相对位移模型是"盘面跟手"
   （ΔRing = Δcss，2026-09-19 用户拍板 + Mac 4/4 复验）。盘面旋转 R = 90 − 180v，
   ΔR = Δcss ⟹ **Δv = −Δcss/180** —— 手指顺时针，值必然减小。要反转只有两条路：
   a) 盘面逆着手势转 —— 直接违背刚拍板的"跟手"直觉；b) 数字排列镜像成 −3 上 / +3 下 ——
   偏离原型 `DIALS.ev`（两盘"0 在正下、满值在正上"的镜像约定），原型与参考图都要跟着改。
2. **物理隐喻本来就是"拖盘读数"，不是"旋钮"**：这是老式收音机调谐盘那类交互——盘跟手转、
   读数看刻度排列；"顺时针=增大"是**旋钮**（固定刻度、转指针）的直觉。两个隐喻都真实存在，
   本项目从 B3a 起选的就是前者（数字刻在盘上、盘跟手）。
3. **B3b 的自洽推论**：对焦盘 mirror=false（数字排列天然镜像），同一模型下
   **对焦盘"顺时针滑 = 值增大"（0 近 → 1 远）** —— 两盘"值方向"相反、但"盘永远跟手"
   完全一致。这是镜像布局的物理自洽：两颗转盘上刻的数字方向相反，拖起来读数方向当然相反。
   若强行统一"顺时针=增大"，必有一盘盘面逆手转 —— 那才是真正反直觉的。
4. 成本收益：改镜像要动原型 + 数字排列 + 重新复验，收益只是"方向跟另一类隐喻一致"；
   EV 是双向对称参数（0 居中），试错成本极低（拖 1 秒就知道方向），不值得动。

（若你仍要改：改动点 = `DialConfig` 里数字排列翻转 + 原型 `DIALS.ev` 同步 + 复验，
工程量约半天，写在档案里备查。）
