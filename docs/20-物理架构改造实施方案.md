## 〇、结论先行

1. **会话形态状态机**：`SessionForm`（`.virtual` / `.physical(FocalPreset)`）由
   `CaptureSessionController` 持有并发布；**触发者是 VM**（用户动作 → VM 请求 → session 执行）。
2. **入口语义升级（核心拍板点 ①）**：按需架构下"手动开关 / 对焦盘"在虚拟会话里**不能再置灰或
   toast 不开盘**——那是唯一入口，点了 = **先切物理（转场）→ 完成后自动执行原动作**。
   "能力探测置灰 / toast 不开盘"的呈现随架构落地退役。
3. **参数搬运顺序**（预检 ⑥）：commit → `applyFormat(新设备)` → `reapplyManualState`（搬运）
   —— 搬运 clamp 依赖新设备 activeFormat。
4. **模糊转场 = 顺序触发**（预检 ⑧）：`isLensSwitching` 两段式——VM 置 true → UI 淡入
   **完成回调**里调 `VM.commitFocalSwitch()` → session 换设备+搬运 → 置 false → UI 淡出。
5. **回切**（预检 ①）：VM 观察三个意图态全空 + 物理会话 → **2s 防抖**（Task）→ 切回虚拟；
   录制中顺延。
6. **zoom 分派**（预检 ⑦）：虚拟 = B1 ramp（现状）；物理同镜头（35↔48）= ramp 到
   `mainCropFactor`（真读）；物理跨镜头 = 换设备流程。

## 一、CaptureSessionController 的 input 管理改动

### 1.1 形态状态机

```swift
/// 会话形态：虚拟多摄（平滑变焦）或物理单摄（手动参数可用）。
enum SessionForm: Equatable {
    case virtual
    case physical(FocalPreset)   // 挂载的焦段档（13/24/35/48/120）
}
// CaptureSessionController：
@Published private(set) var form: SessionForm = .virtual
private var physicalInputCache: [String: AVCaptureDeviceInput] = [:]   // focalId → input
```

- **唯一写入点** = `applyFocalTarget(_ target: FocalTarget)`（下 1.3）；`buildSession()`
  冷启动只建 `.virtual`（现状 `backCamera()` 不动）。
- **`FocalTarget`**：`.virtual` / `.physical(FocalPreset)` —— VM 层把"用户动作"翻译成目标，
  session 只管执行（含幂等：目标 == 当前形态 → no-op）。

### 1.2 物理设备发现（`CaptureCapabilities` 扩展）

```swift
static func physicalDevice(for preset: FocalPreset) -> AVCaptureDevice?
// 13mm → builtInUltraWideCamera；24/35/48 → builtInWideAngleCamera；120 → builtInTelephotoCamera
// DiscoverySession 精确匹配（与既有 hasUltraWideLens / hasTelephotoLens 同源设备类型常量）
```
- 设备不存在的机型：`focalTapped` 对应档位**本就置灰**（B1 既有）→ 不会请求 → 不需要新分支。

### 1.3 换设备六步 + 回滚（预检 ②⑥；docs/18 2.3 顺序不变）

```swift
func applyFocalTarget(_ target: FocalTarget) {   // sessionQueue 上串行执行
    // 【前置，预检 ②】
    //  a) ramp 进行中 → configurator.cancelVideoZoomRamp()
    //  b) state != .running → pendingTarget = target，startInternal() 就绪分支补执行
    //  c) target == 当前形态 → no-op（幂等）
    // 【转场开】publish { isLensSwitching = true }   ← 顺序触发的第 ③ 段由 UI 完成回调触发，
    //                                                详见第四节（本方法由 commitFocalSwitch 调）
    session.beginConfiguration()
    if let old = videoInput { session.removeInput(old) }
    let newDevice = CaptureCapabilities.physicalDevice(for: preset)   // 或虚拟 backCamera()
    // 【回滚】add 失败 → 重新 add 旧 input → commit → 报错保形态（绝不留无 input 的会话）
    guard let input = try? AVCaptureDeviceInput(device: newDevice), session.canAddInput(input) else {
        if let old = old, session.canAddInput(old) { session.addInput(old) }
        session.commitConfiguration()
        publish { lastErrorMessage = "切换镜头失败，已恢复原镜头" }；publish { isLensSwitching = false }
        return
    }
    session.addInput(input); videoInput = input; device = newDevice
    session.commitConfiguration()                                    // ← 铁律 1 分界
    configurator.applyFormat(chooseFormat(for: newDevice), frameRate: 30, to: newDevice)  // ⑥ 先格式
    reapplyManualStateLocked(on: newDevice, from: oldDevice)          // ⑦ 后搬运（第三节）
    configureAudioInputLocked(for: mode)                              // 音频 input 不受影响，保持幂等
    publish { form = target; isLensSwitching = false }
    // 变焦拓扑日志按新设备重打（Mac 核法：deviceType 应变为物理单摄）
    // 对焦降级（预检 ⑤）在 reapplyManualState 内：publish { manualFocus = nil } + toast
}
```

- **`videoInput` / `device` 复用现有属性**（不新建状态）；`physicalInputCache` 暂不做
  （YAGNI——换设备频次低，`AVCaptureDeviceInput(device:)` 每次新建成本可接受；真机若测出
  卡顿再缓存，方案不预置）。
- **音频 / 输出不动**：换 input 不影响 outputs（`.inputPriority` 下 outputs 自适应新设备）；
  `configureAudioInputLocked` 重跑一次保证音频 input 在（幂等，已有 `audioInput == nil` 守卫）。
- **Live Photo 输出**：`photoService.output.isLivePhotoCaptureSupported` 随设备变 —— 换设备后
  该值变化要进日志（预检 ③ 待验数据源）。

### 1.4 排队（预检 ②）

- `state != .running` 时请求 → `pendingTarget` 存住；`startInternal()` 的就绪分支
  （现有 `.running` 订阅处）检查并补执行。
- 执行中重复请求：`isLensSwitching == true` 期间新请求直接忽略（转场期间焦段条已禁点，兜底）。

## 二、参数搬运的具体逻辑（预检 ④⑤⑥；`reapplyManualStateLocked`）

**调用时机**：换设备流程第 ⑦ 步（`applyFormat` 之后 —— clamp 依赖新设备 activeFormat）。
**搬运源** = 换设备前从**旧设备读出的真值**（`manualExposure(of: oldDevice)` /
`manualWhiteBalance(of: oldDevice)` / `session.exposureBias`）—— 曝光/白平衡的 `.custom` /
`.locked` 只能由用户显式设置（系统不会自动进），回读可信（与对焦不同，⑩ 教训不适用）。

| 参数 | 搬运逻辑 | clamp 目标 |
|---|---|---|
| ISO / 快门 | `manualExposure(of: old) != nil` → `setExposureModeCustom(duration:iso:)`，两值 clamp 到**新设备 activeFormat** 域（复用 B2 的 `unavailableStripValues` 同一套 clamp） | 新 activeFormat |
| 白平衡 | `manualWhiteBalance(of: old) != nil` → 旧 **色温** 经 `currentTemperature(of: old)` 兜底链 → `setWhiteBalanceModeLocked`（gains 用新设备 `temperatureAndTintValues` 换算，冷启动无效则 5600K 兜底——既有链路） | 新设备增益域（normalize） |
| **EV**（预检 ④） | `exposureBias`（session 状态）→ `applyExposureBias(clamp 到新设备 bias 域)`；手动曝光档下系统忽略 POI/EV，**值保留在状态里**（回自动档自动生效）——UI 显示值不跳 | 新设备 bias 域 |
| **对焦**（预检 ⑤） | **显式降级，不搬运**：`setAutoFocus(on: newDevice)` + `publish { manualFocus = nil }`（意图清除——⑱ 意图态的换设备执行点）+ toast「已切换镜头，对焦回到自动」+ 日志 | — |

- **搬运失败不致命**：单项 throw → warn 日志 + 该项回自动（逐项 try，不因白平衡失败连累曝光）。
- 搬运完成后 `publishManualState(newDevice)` —— 曝光/白平衡回读应非 nil（搬运成功），
  **Mac 核法：换设备日志后 `manualExposure` / `manualWhiteBalance` 非空**。

## 三、模糊转场的实现（预检 ⑧⑨；docs/18 3.1 顺序触发）

### 3.1 分层与驱动链

```
VM.beginFocalSwitch(preset)        ← 用户点焦段（判定需要换设备时）
  │ publish { isLensSwitching = true; pendingFocalPreset = preset }
  ▼
CameraView（观察 isLensSwitching）
  │ withAnimation(.easeIn(dialBlurIn 0.15)) { blurOpacity = 1 }
  │   completion: { viewModel.commitFocalSwitch() }     ← 顺序触发核心：糊住才切
  ▼
VM.commitFocalSwitch()
  │ session.applyFocalTarget(.physical(preset))          ← 第二节六步
  │ 完成后 publish { isLensSwitching = false }
  ▼
CameraView：withAnimation(.easeOut(dialBlurOut 0.25)) { blurOpacity = 0 }
```

- **浮层本体**：`BlurOverlayView`（新，UIViewRepresentable 包 `UIVisualEffectView`，
  `effect` 由 opacity 属性驱动 —— UIVisualEffectView 的 effect 强度不能直接动画，
  实现 = `UIVisualEffectView` + 外层 UIView.alpha 渐变（业界标准做法），挂在 `PreviewView`
  的 layer 之上、触摸**穿透**（`isUserInteractionEnabled = false`，不影响点按对焦）。
- **时长令牌**：`Theme.Size.dialBlurIn 0.15 / dialBlurOut 0.25`，自检量级守卫 `∈ [0.1, 0.5]`。
- **iOS 18 `withAnimation completion:`**（目标系统 ✓）。
- **禁点**：`isLensSwitching` 期间焦段条 `allowsHitTesting(false)`（防连点叠流程）。
- **不进 `collapseOverlays()`**（纯视觉，无互斥语义，docs/18 3.2 既有结论）。

### 3.2 验收要点（预检 ⑨，写进 Mac 口径）

峰值段"清晰 → 糊 → 黑一瞬 → 糊 → 清晰"是**预期行为**（转场软化跳变，不消灭黑屏）。
顺序触发下模糊在换设备**开始前**已完全盖住画面，切换耗时不影响观感。

## 四、回切策略的具体实现（预检 ①；docs/18 2.2b）

**触发语义**（VM 观察，`Combine` 三个发布源合并）：

```
manualExposure == nil && manualWhiteBalance == nil && manualFocus == nil
  && form == .physical && !isRecording
  → 起 2s 防抖（dialRevertDebounce，Theme 令牌）
  → 到期仍满足 → session.applyFocalTarget(.virtual)（走同款转场：isLensSwitching 两段式）
任一手动档再进 → 取消防抖任务
isRecording 中到期 → 顺延（录制结束再起 2s）
```

- **实现**：`revertDebounceTask: Task<Void, Never>?`——三态合并订阅里 `cancel()` 旧的、
  条件满足时新建 `Task { try? await Task.sleep(for: .seconds(2)); guard 条件仍满足 else return;
  applyFocalTarget(.virtual) }`。不用 Timer（与 sessionQueue 无耦合，最终由 session 串行化）。
- **防抖 2s** = Theme 令牌 `dialRevertDebounce 2.0`，自检守 `∈ [1, 5]s`（docs/18 2.2b 拍板）。
- **"进手动"会取消防抖**：手动开关/对焦开盘（虚拟→物理的那次请求）本身也走
  `beginFocalSwitch`，天然先 cancel。
- **切回后**：参数本就全自动，无需搬运；变焦拓扑日志回到虚拟设备（Mac 核法）。

## 五、跨模式边界的处理（预检 ③；docs/18 2.7）

| 场景 | 规则 | 实现 |
|---|---|---|
| **录制中**（`isRecording`） | **跨镜头切换禁**（换 input 断流毁产物）→ toast；**同镜头数码变焦允许**（35↔48 在同一颗 Wide 上，`applyZoomRamp` 录制中系统支持） | `focalTapped` 分派处 `isRecording` 分支：物理会话 + 目标与当前不同镜头 → toast「录制中不能切换镜头」 |
| **Live Photo 待拍**（模式 = livePhoto） | 允许切换；**Live×13mm 兼容性 = 真机待验**（`isLivePhotoCaptureSupported` 是 output×device 组合值） | 不预置灰；换设备日志打实测值（Mac 待验项 ①），不支持再定"Live 下 13mm 置灰" |
| Log 实况（视频模式） | 同录制中（isRecording 覆盖） | 同上 |
| **对焦盘拖动链回归**（B3b 挂起项） | 物理会话下点「对焦」→ 开盘 → 拖动 → `setManualFocus`（意图入口②已就位，**自动生效**） | 无新代码，验证项 |
| 点按对焦（手动锁定期间） | 只测光（拍板 ③，已上线） | 无新代码 |
| 简易模式（#12 未建） | 无关 | — |

## 六、zoom 分派（预检 ⑦；docs/18 2.5）

`focalTapped` 的分派矩阵（`VM` 层，收敛一个入口）：

| 当前形态 | 目标档 | 动作 |
|---|---|---|
| virtual | 任意档 | B1 现状：`applyZoomRamp`（虚拟切换点平滑） |
| physical | 同镜头档（24↔35↔48，都在 Wide） | `applyZoomRamp` 到 `mainCropFactor`（真读 `FocalPreset`，**物理分支禁字面量 1.458/2.0**） |
| physical | 跨镜头档（↔13 / ↔120） | `beginFocalSwitch` 转场 → `applyFocalTarget(.physical(新档))`（目标档在新设备上 zoom=1.0） |
| 任一 | 录制中跨镜头 | toast 拒绝（第五节） |

- 物理会话内 `videoZoomFactor` 的 clamp 沿用既有 `zoomRange` 逻辑（B1 的 clamp 统一走
  `CaptureCapabilities`）。
- **虚拟路径不得增删 input / 物理路径增删只在换设备方法** —— 第 11 组守卫改口（第八节）。

## 十、Mac 验收口径（要点）

| 事项 | 看什么 |
|---|---|
| 进手动 | 点手动开关 → 转场（糊→黑一瞬→糊→清晰，**预期**）→ 拓扑日志变物理单摄 → 开关不置灰、手动档生效 |
| 搬运 | 进手动 → 调 ISO → 切焦段跨镜头 → 日志显示搬运链（ISO/快门/WB/EV 各一条）+ 开关仍手动、值保留 |
| 对焦降级 | 换设备 toast「已切换镜头，对焦回到自动」；对焦盘读数继续走 |
| 回切 | 全退自动 2s → 日志「切回虚拟多摄」+ 拓扑日志回虚拟 → B1 ramp 恢复 |
| 防抖 | 退自动后 1s 内再进手动 → 不切回（日志无切换） |
| 边界 | 录制中跨镜头 toast 拒绝；35↔48 录制中可变焦 |
| zoom | 物理会话 35→48 ramp 平滑；zoom 值 = mainCropFactor（日志核对） |
| 冷启动 | 待命排队：启动瞬间点焦段 → 就绪后补切 |

## 十一、代价与回滚

- **改动大**：session input 管理重写（本笔主战场）；B1 ramp 分派、B2/B3b 入口语义升级。
- **回滚**：三笔各自 revert；换设备失败自动恢复原 input + toast（不丢会话）。
- **不做会怎样**：手动参数这条产品线整体不可用（B2 置灰 / B3b 入口永远 toast）。
