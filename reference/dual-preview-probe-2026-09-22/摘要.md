# 探针：同一 `AVCaptureSession` 挂多个 `AVCaptureVideoPreviewLayer`（2026-09-22 · 真机）

> 目的：批九（⑥ 视场一致 · 方案 3「满屏 + 窗内 WYSIWYG」）的前置可行性验证。
> 手法：XcodeGen 最小独立 App（bundle id `com.wokenday77.dualpreviewprobe`，同签名团队，**未碰 LumenEdit 工程**），
> 自动跑相位、帧率由同一个 `AVCaptureVideoDataOutput` 计数（三相位数据输出负载恒定，只有"活跃预览连接数"在变）。

## 结论：**不可行** ✗

**同一 session 只能有 1 个预览层出画面 —— 是"最后创建"的那层；其余层的 `connection` 恒为 `nil`（永久黑屏）。**

| 变体 | 层数 | 实测 |
|---|---|---|
| v1 双预览（A 上/绿先建 + B 下/橙后建）| 2 | A = **黑屏**（`active=false enabled=false`）；B = **有画面**（`active=true`）|
| v2 三层（L1 上/绿 · L2 中/橙 · L3 下/青，按序创建）| 3 | L1/L2 = **黑屏** 且 **`connection == nil`**；L3（最后建）= **有画面**（`active=true enabled=true`）|
| v2 追加：运行中把 L1 **摘出图层树再挂回**（+ 再 enable）| — | **无效** ✗ —— L1 `connection` 仍为 `nil`、仍黑屏（0s / 5s 两次采样一致）|

## 附带观测（都无异常）

- **帧率不受影响**：v1 三相位 **30.0 / 30.0 / 30.0 fps**；v2 **34.9 fps**（同一输出计数口径）
- **无报错、无打断、无黑屏类重启**：`runtimeError` / `wasInterrupted` / `didStopRunning` 均未出现；`didStartRunning` 正常
- `isEnabled` 读写在**拿到连接的那层**上跟手有效（B: false→true ✓）；在 `connection == nil` 的层上是空操作（可选链 nil）
- 现象与"哪层在屏幕上更靠上/更大"无关，只与**创建顺序**相关（v1/v2 一致：最后一个 `AVCaptureVideoPreviewLayer(session:)` 赢）

## 对批九的意义

方案 3 的核心前提（同一 session 挂两个预览层）**不成立** ✗ ⇒
- 退方案 1（**届时用户二次拍板**）；或
- 第二条画面改由 **`AVCaptureVideoDataOutput` 自绘**（CAMetalLayer / UIView 逐帧贴图）——属另一条实现路径，需另立方案评估（成本/功耗/延迟）。
